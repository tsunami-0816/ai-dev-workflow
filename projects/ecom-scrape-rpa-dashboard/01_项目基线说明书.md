## 1. 项目核心目标

- **核心问题**：已有项目 #20 `dev-metrics-dashboard` 的数据源是本地项目产物，只证明「看板出数」，不能证明「电商多平台取数 → 反爬应对 → 清洗校验 → RPA 流程化补采 → Excel 日报 → BI 看板」这一整条外网数据生产线；求职侧 G1 缺口（乐福思杰士邦 电商爬虫工程师 J10888、索骥数据「数据抓取开发经验」加分项）无落地证据。
- **业务价值**：以「某品牌（避孕套/润滑剂品类）在 3 个平台的价格与销量监控」为业务壳，交付一条可复现、可观测、可回归的数据生产线：每天 02:00 采集、08:00 出 Excel 日报与 Web 看板，采集成功率/封禁率/P95 耗时上板，数据可回溯到 `raw_page` 快照，报表公式可重算且能与 DB 三方对账差异为 0。
- **项目成立的判定（MVP 唯一场景）**：`targets.yaml` 配置 → 4 站点适配器采集（≥3 个平台）→ 反爬策略生效 → pandas 清洗校验落 MySQL → YAML RPA 流程补采登录态页面 → 生成 5 个 sheet 的 Excel 日报 → Vue3/ECharts 看 4 个视图。**做完这件事，项目就算成了**。
- **诚实边界**：不伪造「2 年电商爬虫从业经历」；不伪称用过 FineBI（以 ECharts 等价实现 + FineBI 口径迁移文档证明）；演示环境用自有 mock 站点时，指标如实标注「mock 环境」。

## 4. 约束条件

- **技术栈约束**：Python 3.11 + APScheduler；httpx（异步）/ requests；Playwright（Chromium）同时作浏览器采集与 RPA 内核；parsel/lxml + 正则 + JSON 路径；pandas；MySQL 8（按日分区）；openpyxl；FastAPI；Vue3 + ECharts；pytest；Docker Compose。明确不用 Scrapy、不用分布式集群、不用云函数。
- **部署环境约束**：本地单机 Docker Compose（MySQL 8 + app + nginx），一键起、不依赖云；Excel 公式须经 LibreOffice headless 重算校验一次（规避非 Windows 打开异常）；`raw_page` 原始快照落文件、表存指针。
- **资源约束**：总工作量 5.0 人天（M1 1.3 / M2 1.0 / M3 0.7 / M4 0.7 / M5 0.7 / M6 0.5），≤5 人天预算；无真实登录账号、无商业代理、无验证码识别服务；按域名独立配额（基准 1 次/1.5s），并发上限京东 4 / 天猫 2 / 拼多多 2 / 抖音 1。
- **时间约束**：每日 02:00 触发采集、08:00 生成 Excel 日报并写 `report_file`；RPA 每步默认超时 15s、重试 2 次；Excel 日报生成 <10s；看板首屏 P95 <1.5s；单项目排产按队列期 2 双工位推进。
- **合规约束**：只采集公开可见的商品信息（标题/价格/销量标签/评价数），遵守目标站点 `robots.txt` 与用户协议；不绕过登录墙与付费墙、不破解加密接口、不存储个人隐私；Cookie/账号仅用本地测试账号、用完即清；检测到验证码转人工队列；演示用自有 mock 站点时指标如实标注「mock 环境」。以上边界写进 README 与验收材料。
