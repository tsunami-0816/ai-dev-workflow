# 项目设计书 · web3-dapp-voting（Solidity 智能合约 + React DApp）

> 目的：补 JD 缺口——证明"能写 Solidity 智能合约 + 部署测试链 + 前端连接钱包交互"，对口坤汇高新 Web3 岗。
> MVP 原则：不做复杂 DeFi（DEX/借贷/流动性挖矿），只做 ERC20 代币 + 投票合约两个核心合约，前端连接 MetaMask。

## 1. 项目一句话
用 Solidity ^0.8 写一个基于 OpenZeppelin 的 ERC20 代币合约 + 简单投票合约，Hardhat 本地测试链部署，React + Vite 前端连接 MetaMask 钱包，实现查余额、转账、投票全流程。

## 2. MVP 最小可用场景（必须能做完）
启动 Hardhat 本地节点 → 部署 ERC20 代币合约和投票合约 → MetaMask 切换到本地测试链 → 前端页面显示当前地址代币余额 → 点"转账"给另一个地址 → MetaMask 弹窗确认 → 余额更新 → 点"投票"给候选方案投票 → 链上投票结果实时显示 → 用 Hardhat 单元测试覆盖部署/转账/投票场景。

**做完这件事，项目就算成了。** 不做主网部署、不做 DeFi 流动性、不做 NFT、不做跨链桥、不做 Staking。

## 3. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 智能合约语言 | **Solidity ^0.8** | 强类型，不写 0.7 以下版本 |
| 开发框架 | **Hardhat** | 本地链 + 部署脚本 + 测试 + console |
| 合约库 | **OpenZeppelin Contracts** | ERC20 标准实现，不自己造轮子 |
| 前端 | **React 18 + Vite + TypeScript** | 轻量页面 |
| 钱包交互 | **Ethers.js v6** | 连接 MetaMask，发交易，读合约 |
| 钱包 | MetaMask 浏览器插件 | 用户自己装 |
| 测试 | **Hardhat Network + Chai** | 合约单元测试 |

**明确不做**：主网部署（花真钱）、Uniswap/DeFi 协议、NFT/ERC721、跨链、IPFS存储、后端索引节点（The Graph）、钱包后端（只用 MetaMask）。

## 4. 核心模块（P0，只做这些）

### 模块1：ERC20 代币合约（0.5d）
- 继承 OpenZeppelin ERC20 + Ownable
- mint（只有 owner 能铸币）、transfer、balanceOf
- 名称"VoteToken"，符号"VT"，初始供应 100 万枚给部署者
- 写单元测试：部署→查余额→转账→余额变化→权限校验

### 模块2：投票合约（1d，**核心**）
- 合约存储：候选方案列表（Proposal[]），每个方案有 name + voteCount
- 每个地址只能投一票（mapping(address => bool) hasVoted）
- 投票函数：vote(uint proposalIndex)，检查未投过 → voteCount++ → hasVoted[msg.sender]=true
- 查询函数：getProposals() 返回所有候选方案及票数
- 时间锁（可选加分）：投票开始/结束时间
- 写单元测试：部署→投票→重复投票被拒→查结果

### 模块3：Hardhat 部署脚本与配置（0.5d）
- hardhat.config.js：配置本地网络、Solidity 编译器版本
- scripts/deploy.js：部署 ERC20 + Voting 两个合约，打印合约地址
- 启动 npx hardhat node 本地链（端口 8545）
- MetaMask 添加本地网络（rpc=http://127.0.0.1:8545, chainId=31337）

### 模块4：React 前端 DApp（1.5d）
- 连接 MetaMask 按钮：window.ethereum.request 授权
- 显示当前连接地址 + ERC20 代币余额（调用 balanceOf）
- 转账表单：输入接收地址 + 数量 → MetaMask 确认 → 余额更新
- 投票面板：列出所有候选方案 + 票数 → 点投票按钮 → MetaMask 确认 → 票数更新
- 交易状态提示：pending/confirmed/reverted
- 用 ethers.js v6 的 BrowserProvider + Contract 实例

### 模块5：测试与 README（0.5d）
- Hardhat 测试覆盖：ERC20 部署/转账/权限，Voting 投票/重复投票/查结果
- README 写清：怎么起本地链、怎么部署合约、怎么连 MetaMask、怎么跑前端
- 贴合约地址截图 + MetaMask 交易确认截图

## 5. 量化基线指标

| 编号 | 指标 | 验证方式 |
|---|---|---|
| M1 | ERC20 合约部署成功，初始余额正确 | Hardhat console 打印 |
| M2 | 转账交易上链，双方余额正确变化 | 测试用例断言 |
| M3 | 投票合约部署成功，投票后票数增加 | 测试用例断言 |
| M4 | 同一地址重复投票被拒绝（revert） | 测试用例断言 |
| M5 | MetaMask 连接前端成功，显示地址和余额 | 浏览器手动验证 |
| M6 | 前端投票按钮触发 MetaMask 弹窗，确认后票数更新 | 手动操作验证 |
| M7 | Hardhat 测试全部通过（≥8 个测试用例） | npx hardhat test 全绿 |

## 6. 数据模型
- 链上数据（合约存储）：
  - ERC20：mapping(address => uint256) balances, uint256 totalSupply
  - Voting：Proposal[] proposals {string name, uint voteCount}, mapping(address => bool) hasVoted
- 前端状态：当前地址、连接状态、合约实例、交易状态
- 无后端数据库，所有数据在链上
