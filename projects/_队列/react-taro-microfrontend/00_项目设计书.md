# 项目设计书 · react-taro-microfrontend（React跨端H5/小程序 + qiankun微前端）

> 目的：补 JD 缺口——证明"React 主力栈 + 跨端开发 + 微前端架构能力"，对口连帆科技/九凌科技/高帆破浪/伯遇智能/垦驱智能。
> MVP 原则：不做复杂业务，重点是把 React 18 + Taro 跨端 + qiankun 微前端三个硬技能做扎实，业务页面从简。

## 1. 项目一句话
基于 React 18 + TypeScript + Taro 4 构建跨端应用（一套代码出 H5 + 微信小程序），React 主应用通过 qiankun 微前端框架挂载已有 Vue3 子应用，验证主子应用通信与样式隔离，Docker Compose 部署 Nginx 静态资源。

## 2. MVP 最小可用场景（必须能做完）
用户在 H5 端打开应用 → 登录页输入账号密码 → 进入列表页看到商品列表 → 点进详情页看商品详情 → 切换到"子应用"Tab → qiankun 加载出 Vue3 子应用页面（复用 #7 SaaS 工作流的 Vue3 代码）→ 主子应用之间能通信（主应用传用户信息给子应用，子应用回传操作事件）→ 微信小程序端同样跑通登录+列表+详情三个页面。

**做完这件事，项目就算成了。** 不做支付、不做购物车、不做后端复杂业务、不做 React Native 原生编译（Taro 跨端原理和 RN 思路一致即可）。

## 3. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 主框架 | **React 18 + TypeScript + Hooks** | 函数组件 + Hooks，不用 class |
| 跨端 | **Taro 4** | 一套代码编译 H5 + 微信小程序 |
| 构建 | Vite | Taro 4 内置 Vite 模式 |
| UI | Ant Design 5（H5端）+ Taro UI（小程序端） | H5 用 antd，小程序用 Taro 组件库 |
| 微前端 | **qiankun 2.x** | React 主应用挂载 Vue3 子应用 |
| 路由 | React Router 6 | H5端路由 |
| 状态管理 | **Zustand** | 轻量，比 Redux 简洁 |
| HTTP | Axios + 拦截器封装 | Token 刷新 + 统一错误处理 |
| 后端 | 已有 Spring Boot 项目复用（#7 SaaS工作流后端） | 不新写后端，复用现有 API |
| 部署 | Docker Compose + Nginx | 静态资源容器化部署 |

**明确不做**：React Native 原生端编译（Taro 跨端原理已覆盖）、wujie（只做 qiankun）、微前端多级嵌套（只做一级主+子）、微应用独立部署流水线（本地跑就行）。

## 4. 核心模块（P0，只做这些）

### 模块1：Taro 跨端基础框架（1d）
- Taro 4 初始化项目，配置多端编译（H5 + 微信小程序）
- 配置项目目录结构（pages/components/utils/services）
- 跑通 H5 端 dev server 和小程序端微信开发者工具预览
- 封装 Taro.request 和 Axios 的统一请求层（H5 用 Axios，小程序用 Taro.request，同一接口抽象）

### 模块2：业务页面（1.5d）
- 登录页：表单校验 + 登录态存 localStorage/Taro.storage
- 列表页：商品列表（调已有后端接口），下拉刷新 + 上拉加载
- 详情页：商品详情展示，图片轮播
- 个人中心：用户信息展示 + 退出登录
- H5 端用 Ant Design 组件，小程序端用 Taro UI 组件，同一套业务逻辑

### 模块3：qiankun 微前端集成（1.5d，**核心亮点**）
- React 主应用入口注册 qiankun：registerMicroApps 配置 Vue3 子应用入口
- 子应用：复用 #7 SaaS工作流的 Vue3 代码，改造成 qiankun 子应用格式（导出 mount/unmount/bootstrap 生命周期）
- 主子应用通信：qiankun initGlobalState 传用户登录态给子应用，子应用回传操作事件
- 样式隔离：验证 qiankun 的 strictStyleIsolation  ExperimentalStyleIsolation
- 主应用路由切换到 /subapp 时加载子应用，切回时卸载

### 模块4：状态管理与请求封装（0.5d）
- Zustand 管理全局状态（用户信息、登录态、主题）
- Axios 拦截器：请求自动带 Token，响应 401 自动跳登录，统一错误提示
- Token 刷新机制：401 时用 refresh_token 换新 Token 重试原请求

### 模块5：Docker 部署（0.5d）
- Dockerfile 构建 H5 端静态资源
- Nginx 配置：H5 路由 history 模式 fallback + qiankun 子应用静态资源路径
- Docker Compose 一键起 Nginx 容器

## 5. 量化基线指标

| 编号 | 指标 | 验证方式 |
|---|---|---|
| M1 | Taro 一套代码同时编译出 H5 和微信小程序两端产物 | 跑 build:h5 和 build:weapp，两个目录都有产物 |
| M2 | H5 端登录→列表→详情→个人中心四页全通 | 浏览器手动点一遍 |
| M3 | 微信小程序端登录→列表→详情三页全通 | 微信开发者工具预览 |
| M4 | qiankun 在 React 主应用里成功加载 Vue3 子应用 | 主应用切到 /subapp 能看到 Vue3 页面渲染 |
| M5 | 主子应用通信：主应用传用户信息给子应用，子应用 console 能收到 | 浏览器 devtools 验证 |
| M6 | Axios 拦截器生效：未登录访问自动跳登录，401 自动刷新 Token | 手动测 401 场景 |
| M7 | Docker Compose 一键起 Nginx，浏览器访问能看到 H5 页面 | docker compose up 后访问 localhost |

## 6. 数据模型
- 复用已有 #7 SaaS工作流后端的 users/products 接口，不新建数据库表
- 前端状态：Zustand store 存用户信息、Token、登录态
- localStorage / Taro.storage 存 Token（持久化刷新不掉登录态）
