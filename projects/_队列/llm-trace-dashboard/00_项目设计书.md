# 项目设计书 · LLM Trace Dashboard（LLM 调用追踪看板 v2）

> 返厂重做：v1（llm-eval-observability）因范围过大（SDK 自动注入/ClickHouse/Qdrant/Go/RabbitMQ）搁置，本版砍到手动录入 + SQLite 看板 MVP。
> 可复用 v1 资产：三张表（traces/prompts/eval_cases）的字段设计，见 `_archive_v1/llm-eval-observability-v1/backend/main.py`。

## 1. 项目一句话
用户在页面上手动录入一次 LLM 调用记录（模型/输入/输出/延迟/成本），ECharts 看板上看到延迟趋势、成本统计、成功率，把答错的标记为 bad case。

## 2. MVP 最小可用场景（必须能做完）
用户打开看板 → 点"录入调用"→ 填模型（deepseek-chat）、输入（"你好"）、输出（"你好，有什么可以帮你"）、延迟（800ms）、成本（0.0002 元）→ 提交 → 看板刷新：延迟折线图多了一个点、总成本卡片涨了一点、最近调用列表多了一行 → 用户点开一条答错的记录，勾"标记为 bad case"→ 列表筛选"只看 bad case"→ 那条记录单独显示。

**做完这件事，项目就算成了。** 不做 SDK 自动注入、不做自动评测。

## 3. 技术栈（砍到最小）

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Python FastAPI | CRUD + 聚合查询 |
| 数据库 | SQLite（单文件，**不引入 MySQL/ClickHouse/Qdrant**） | 轻量，16GB 内存无压力 |
| 前端 | Vue3 + Vite + ECharts + Element Plus | 看板图表 + 录入表单 + 列表 |
| LLM-as-judge | **不做**（bad case 手动标注） | 砍掉自动评分 |

**明确砍掉 v1 的东西**：Python SDK 自动注入、Go 性能热点、ClickHouse、Qdrant 向量检索、RabbitMQ 异步评测、LangChain/LangGraph/CrewAI 框架适配、Agent 链路树、Prompt A/B 对比（只存版本不做对比）、Redis。

## 4. 核心模块（P0，只做这些）

1. **Trace 录入表单**：页面表单填 project/model/input/output/latency_ms/tokens/cost，POST `/api/traces`。
2. **Trace 列表页**：表格显示最近 100 条，支持按 project/model/is_bad 筛选，点行展开看 input/output 全文。
3. **Bad case 标注**：每条 trace 有 `is_bad` 开关，列表筛选"只看 bad case"。
4. **Dashboard 看板**：
   - 顶部卡片：总调用数、平均延迟（ms）、总成本（元）、bad case 数
   - 延迟趋势折线图：最近 50 条的 latency_ms 按时间排列
   - 模型分布饼图：按 model 分组统计调用数
   - 每日调用量柱状图：按 ts 日期分组
5. **Prompt 版本管理（极简）**：只做列表展示（名称/版本/内容），不做 A/B 对比。

## 5. 量化基线指标（可验证）

| 编号 | 指标 | 验证方式 |
|---|---|---|
| M1 | 录入一条 trace 后，列表和看板数字立即更新 | step6 冒烟手动录入 1 条 |
| M2 | 录入 10 条不同模型的 trace，饼图能正确分组 | step6 录入验证 |
| M3 | 延迟折线图能渲染最近 50 条 | step6 截图 |
| M4 | bad case 标注后，筛选"只看 bad case"只显示标注项 | step6 操作验证 |
| M5 | 最近 100 条列表查询 < 200ms | step8 性能验证（SQLite 足够） |

## 6. 数据模型（直接复用 v1 表结构）

- `traces`：id, project, model, input, output, latency_ms, tokens, cost, is_bad(INTEGER 0/1), ts
- `prompts`：id, name, version, content, ts
- （eval_cases 表 v2 不做，bad case 直接用 traces.is_bad 标记）

## 7. JD 技能点覆盖

| JD 技能点 | 落点 |
|---|---|
| Python FastAPI | 后端主栈 |
| RESTful API + Pydantic | 数据校验 |
| ECharts 可视化 | 看板图表 |
| SQL 聚合查询（GROUP BY/AVG/SUM） | 看板统计接口 |
| 前端表格 + 表单 + 筛选 | Trace 列表页 |

> v1 里的"SDK 自动注入/ClickHouse/Qdrant/Agent 链路追踪"本期不做，面试时诚实说明"轻量版聚焦手动录入 + 可视化分析，自动采集留待二期"。
