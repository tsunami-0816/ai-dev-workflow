# 项目设计书 · Light Workflow Studio（轻量流程画布 v2）

> 返厂重做：v1（saas-workflow-agent）因范围过大（多租户/DAG/多Agent/MQTT/Qdrant）搁置，本版砍到线性流程 MVP。
> 可复用 v1 资产：后端端口 8083、前端端口 5177、Workflow/WorkflowRun 实体字段思路。

## 1. 项目一句话
用户在画布上拖 3 种节点（开始 / HTTP 请求 / LLM 调用 / 结束），连线成线性流程，点执行能看到每一步的真实返回结果。

## 2. MVP 最小可用场景（必须能做完）
用户打开画布 → 点"加 HTTP 节点"→ 双击节点填 `https://jsonplaceholder.typicode.com/todos/1` → 加一个"LLM 节点"→ 双击填"把上一步返回总结成一句话"→ 连线 start→http→llm→end → 点"执行"→ 画布下方实时显示每步的输入、输出、耗时 → 最后看到 LLM 总结结果。

**做完这件事，项目就算成了。** 不做多租户、不做分支、不做并发。

## 3. 技术栈（砍到最小）

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Java 17 + Spring Boot 3（**单模块，不用 Cloud**） | 流程定义 CRUD + 执行引擎 |
| 前端 | Vue3 + Vite + AntV X6 + Element Plus | 画布编排 + 执行日志面板 |
| 数据库 | MySQL 8（单库） | workflow_def / workflow_run / workflow_step 三表 |
| LLM | DeepSeek API（HTTP 调用） | LLM 节点真调，不做本地模型 |
| 部署 | 本地直接跑（不做 Docker Compose） | 开发期 mvn spring-boot:run + npm run dev |

**明确砍掉 v1 的东西**：Spring Cloud、RabbitMQ、Redis、Qdrant、EMQX MQTT、多 Agent（CrewAI/LangGraph）、模型路由、NL 转流程、分支条件、错误重试、SSE（用前端 2 秒轮询代替）、多租户。

## 4. 核心模块（P0，只做这些）

1. **X6 画布基础**：加节点、拖线连接、删节点、双击弹配置面板。**不做**对齐线、小地图、缩略图。
2. **节点配置面板**：
   - HTTP 节点：填 URL、Method（GET/POST）、Header（简单 key-value）
   - LLM 节点：填 prompt 模板，支持 `{{step1.output}}` 引用上一步输出
3. **线性执行引擎**：按连线拓扑从 start 顺序走到 end（不做 DAG 拓扑排序，不做分支并行）。每步执行结果存 workflow_step 表。
4. **执行日志面板**：右侧列表显示每步状态（pending/running/success/failed）、输入摘要、输出摘要、耗时。执行完后前端轮询 `/api/runs/{id}/steps` 刷新。
5. **HTTP 节点真实调用**：用 RestTemplate 真发请求，状态码、响应体存库。
6. **LLM 节点真实调用**：HTTP 调 DeepSeek `/chat/completions`，把上一步输出拼进 prompt，返回内容存库。

## 5. 量化基线指标（可验证）

| 编号 | 指标 | 验证方式 |
|---|---|---|
| M1 | 画布支持加 ≥5 种节点类型（start/http/llm/end） | step6 冒烟手动加 4 种节点 |
| M2 | 节点之间能拖线连接，至少支持 3 节点串联 | step6 冒烟拖 start→http→llm→end |
| M3 | HTTP 节点真调外部 API，返回状态码 200 | step6 用 jsonplaceholder 验证 |
| M4 | LLM 节点真调 DeepSeek，返回非空总结文本 | step6 验证返回内容 |
| M5 | 执行一个 3 节点流程，每步输入/输出/耗时落库 | step7 联调查 DB |
| M6 | 执行日志面板能看到每步状态 | step6 前端截图 |

## 6. 数据模型（保留 v1 思路，精简）

- `workflow_def`：id, name, definition_json（X6 导出的节点+边）, created_at
- `workflow_run`：id, workflow_id, status(RUNNING/SUCCESS/FAILED), started_at, finished_at
- `workflow_step`：id, run_id, node_key, node_type, input_snapshot, output_snapshot, status, duration_ms, created_at

## 7. JD 技能点覆盖（保留 v1 核心项，砍掉企业级部分）

| JD 技能点 | 落点 |
|---|---|
| Java Spring Boot/MySQL | 后端主栈 |
| Vue3 + AntV X6 画布 | 前端编排 |
| RESTful API 设计 | 执行引擎 API |
| HTTP 客户端调用 | HTTP 节点 |
| LLM API 集成 | LLM 节点（DeepSeek） |
| 异步执行 + 轮询 | 执行引擎 + 前端轮询 |

> v1 里的"多租户/MQTT/CrewAI/Qdrant/模型路由"本期不做，面试时诚实说明"轻量版聚焦流程编排核心链路，企业级能力留待二期"。

## 8. 工作量预估

- 前端（X6 画布 + 配置面板 + 日志面板）：3 人天
- 联调 + 冒烟 + 测试：2 人天
- **合计 8 人天**，在 15 人天预算内。
