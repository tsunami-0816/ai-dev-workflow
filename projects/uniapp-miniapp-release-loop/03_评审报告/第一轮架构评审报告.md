## 1. P0 问题（1 条）

### P0-01 后端"复用 #7 `saas-workflow-agent` 骨架"无法落地
- **问题描述**：架构 §1、§7 与基线 §4.1 都写"复用 #7 `saas-workflow-agent` 的 Spring Boot 骨架，只加 3 接口"。实测 `D:\lg\project` 下**不存在** `saas-workflow-agent` 仓库；可用的 Spring Boot 工程只有两个：`enterprise-rag-java`（Spring Boot **3.2.10** + Java **17** ✅）与 `medicine-query-system-main/backend`（Spring Boot **2.7.4** + Java **1.8** ❌，与 Java 17 要求冲突）。5A 按现文档开工会卡在"骨架在哪"。
- **影响范围**：5A 全部（无工程 = 无接口 = C02/C03/C05/C06/C12 全为 0），连带 L2–L5 断链。
- **严重等级**：P0（命中定义第 ③ 条"选型无法落地"）
- **修改建议**：
  1. 把骨架来源改为 **`enterprise-rag-java`**：只继承它的 `spring-boot-starter-parent 3.2.10` + Java 17 + 包结构/统一响应约定，**不复制任何业务代码**；
  2. 明确"新建独立 module `booking-service`，独立 database `uniapp_booking`"，与源工程只共享 parent/BOM，不共享运行实例；
  3. 若用户手里确有 #7 仓库的其他路径，需在第 3 步人工卡点提供绝对路径，架构再回填；否则按上条执行。

## 2. P1 问题（9 条）

### P1-01 C05 幂等语义错误：报错 ≠ 幂等，且存在"10 分钟假锁"
- **问题**：架构写"SETNX 命中 → 42901 重复提交 → 前端提示已提交过"。但用户若改了个备注想重提，会被 Redis 锁 10 分钟拒掉；同时若 SETNX 成功而 DB 唯一索引冲突（并发），幂等键已占，无法自助恢复。
- **影响**：C05 用例虽能过（计数=1），但真实体验与"幂等"定义相反（幂等应返回**首次结果**而非报错）。**等级 P1**。
- **建议**：改为**幂等返回**：SETNX/查询命中时，读 `booking` 该行并返回原 `bookingId` + `code=0` + `duplicated:true`；仅当 DB 抛 `DuplicateKeyException` 时回滚幂等键并返回同一单号。前端按 `duplicated` 展示"这是你的同一笔预约"。

### P1-02 C04 命中率口径不可验证
- **问题**：缓存 key 按页拆分（`ub:pkg:list:{page}:{size}`），20 次请求若各页不同则命中率天然偏低；文档未定义"命中率按哪个前缀统计、样本怎么取"。
- **等级 P1**（指标无机制保证）。
- **建议**：① 命中率口径 = `INFO stats` 中 `keyspace_hits/(hits+misses)`，且**只统计请求开始/结束差值**（不是实例累计值）；② 样本固定为"同参数 `page=1&size=10` 连续 20 次"；③ 首请求回源时写缓存，命中后 300s 内不再回源；④ 增加 `ub:pkg:list` 单 key + 内存分页方案（避免页数膨胀稀释命中率）。

### P1-03 C03 P95 采样与冷启动未定义
- **问题**：文档只说"云函数 `elapsedMs` 落 csv，≥20 样本算 P95"，没定义采样脚本、并发/串行、冷启动处理，也没有含"前端→云函数"网络段。首次冷启动必 >1s，会直接把 P95 拉爆。
- **等级 P1**。
- **建议**：新增 `scripts/latency_probe.py`：串行 20 次 `POST /api/bookings`；**第 1 次标记为 cold 单列不计入 P95**；P95 用 nearest-rank（第 19 个值）；同时记录云函数 `elapsedMs` 与后端 `Server-Timing`，两个口径都落盘。

### P1-04 C11 设计稿还原缺机制
- **问题**：基线写"自建 375 基准标注稿 → 双端跑 → 叠图比对偏差 ≤8px"，架构文档里没有任何"标注稿从哪来、产物是什么、怎么量"的链路。
- **等级 P1**。
- **建议**：5B 产出 `05_代码/frontend/design/annotations.md`（≥10 条：元素 / 设计值 / 实测值 / 偏差 px / 结论）+ `overlay-375.png`（截图与标注稿 50% 叠图）。标注稿直接由方向稿 A（`门面页方向稿-A.png`）按 375×812 重绘为标注版。

### P1-05 C12 契约来源缺失
- **问题**：6.5 步要用 `openapi.json` 跑 `api_contract_validator.py`，但架构没定义 openapi 由谁生产。
- **等级 P1**。
- **建议**：5A 引入 `springdoc-openapi-starter-webmvc-ui 2.6.x`，暴露 `/v3/api-docs`，导出为 `06.5_契约/openapi.json`；契约基线 = §6.3 的 5 个接口 + 统一响应包装 + 3 个必带请求头。

### P1-06 C13 测试架构缺失
- **问题**：基线要求 pytest ≥15 条 L1+L2 用例、0 failed，架构文档没有测试分层、`base_url` 注入、用例数据隔离、Allure 接入的设计。
- **等级 P1**（第 8 步会临时拍脑袋）。
- **建议**：新增 § 测试架构：`08_测试/qa-automation/{unit,api,contract,e2e}/`；`conftest.py` 提供 `base_url`（默认 `http://127.0.0.1:8092`）、`auth_headers`、`clean_booking`（用例前按 phone 清行）；每用例独立手机号（`1380013{序号}`）；Allure 结果落 `allure-results/`。

### P1-07 安全机制不全（C14 缺抓手）
- **问题**：只有 secrets 扫描 + JWT + HMAC；缺 ① 依赖漏洞扫描工具；② HMAC 重放防护（仅 ±60s 时间窗可重放）；③ JWT 注销/踢人（2h 内无法失效）；④ 渗透用例清单。
- **等级 P1**。
- **建议**：① `npm audit --audit-level=high` + Maven `org.ow2.asm`/`dependency-check-maven` 两条；② HMAC 增加 `X-Nonce`，Redis `ub:nonce:{nonce}` TTL 120s 去重；③ JWT 加 `ub:jwt:blacklist:{jti}`（登出写入，TTL=剩余有效期）；④ 8.5 步渗透清单固定 6 条（无 token 访问写接口 / 越权读他人单 / 手机号注入 / 日期越界 / 超大 body / 非 JSON content-type）。

### P1-08 设计要素清单漏项（会让第 4 步映射表漏抄两项 JD 能力）
- **问题**：JD 对账里的"浏览器兼容性对照（Chrome + 微信内置浏览器）"与"双端差异表"在 D-01–D-32 中没有对应条目。
- **等级 P1**（第 4 步按清单抄，漏了就等于不做）。
- **建议**：补 `D-33 双端差异表（登录/请求/样式/分享能力逐项对照）`、`D-34 浏览器兼容对照（Chrome + 微信内置浏览器，记录滚动/安全区/字体差异与修法）`、`D-35 隐私协议声明与采集项一致性核对表`。

### P1-09 内存与工具并发不可行
- **问题**：本机可用内存实测仅 1.2GB（env_preflight 20261118）。微信开发者工具是 Electron 应用，常驻约 0.8–1.2GB；再加 JVM 512MB + Node 256MB + 浏览器预览，**同时打开一定 OOM**。架构 §7.1 只写了"只起 1 JVM + 1 Node"，没写开发者工具怎么排。
- **等级 P1**（环境可行性，会直接卡 6/7/9 步）。
- **建议**：加"分时运行矩阵"：
  | 阶段 | 常驻 | 停掉 |
  |---|---|---|
  | 5A/5B 编码 + 单测 | MySQL/Redis/MQ + 后端 8092 | 开发者工具、H5 dev |
  | 5B 小程序侧联调 | 开发者工具 + 云函数 8093 + 后端 8092 | H5 dev、浏览器 |
  | 6 冒烟 / 7 联调 | 后端 + 云函数 + H5 dev | 开发者工具（仅截图时打开 3 分钟） |
  | L6 体验版/提审 | 开发者工具 | 后端（提审不依赖本地后端；真机走云/本机同一台机则保留） |
  并且后端固定 `-Xmx512m`、Node `--max-old-space-size=256`。
