## 1. 项目核心目标

**要解决的问题**：求职侧 G9 能力簇（uni-app 一套代码出 H5 + 微信小程序，并走完「体验版真机 → 提审 → 审核 → 发布 → 回滚」）没有任何作品能证明。已有 `react-taro-microfrontend`（React + Taro + qiankun）只证明了「开发者工具里的页面能跑」，**不含真机体验版、不含提审发布**——而 6 份目标 JD（伯遇智能、星光兔摄影、灰豚科技、高帆破浪、云联慧算、雄伟科技）里有 4 家把「小程序 / uni-app」写进 must 或明确加分。

**业务价值**：交付一套「写真预约」业务系统（H5 + 微信小程序双端同一套 Vue3+TS 代码），并在真实小程序后台完成一次完整的**发布闭环**，形成可面试讲解、可演示、有截图证据的四件套（体验版二维码、提审记录、线上版本、回滚记录）。

**本次不做**：不是为了做一个写真店业务，业务只是载体；**发布闭环证据链**才是真正的交付物。

## 3. 项目范围界定

### 3.1 核心范围（必须做）

| 范围项 | 具体内容 | 决策理由 | 对应主链路/来源 |
|---|---|---|---|
| 双端 uni-app 工程 | Vue3 + TS + Vite CLI 工程，`manifest.json` / `pages.json`（5 页 + tabBar），条件编译 `#ifdef H5` / `#ifdef MP-WEIXIN` | 因为缺了它 H5 与小程序两条产物链都没有，C01 直接为 0，整个项目无从谈起 | L1；设计书 M1 |

| 后端 3 个 RESTful API | `GET /api/packages`、`GET /api/packages/{id}`、`POST /api/bookings`，统一 `code/message/data` 包装 | 因为缺了接口，前端只能内嵌 Mock，C02 只是「假页面」，C12 契约校验无对象 | L3–L4；设计书 M3 |

## 4. 约束条件

### 4.1 技术栈约束
- 前端：uni-app（Vue3 + **TypeScript** + Vite）、uni-ui + 自写 rpx 样式；不引入 Tailwind / qiankun / Taro。
- 后端：Spring Boot 3.x + Java 17（**复用 #7 `saas-workflow-agent` 的 Spring Boot 骨架**，只加 3 个接口与 3 张表，不新起一套服务）；MySQL 8、Redis 7、RabbitMQ 3.x。
- 小程序侧：微信小程序（mp-weixin）+ Node.js 20 云函数代理。
- 接口风格：RESTful（JSON），统一 `code/message/data`。

### 4.2 部署/运行环境约束
- 本机 Windows + 16GB 内存；中间件优先用已有 Docker 实例（MySQL/Redis/RabbitMQ），端口按 `WORKFLOW_端口分配表.md` 分配，不抢占用中的 3306/6379/5672。
- 微信开发者工具需真实微信扫码登录（Agent 不能自动化），**这是硬外部依赖**。
- 小程序主体：个人主体，服务类目走「工具 / 生活服务-预约」；不走电商交易类目。

### 4.3 资源约束
- 单项目预算 ≤ 5 人天（设计书 4.5 人天：M1 0.8 / M2 1.2 / M3 1.2 / M4 0.8 / M5 0.5）。
- 内存不得同时起 ≥3 个 JVM 重服务；磁盘上不保留多份构建缓存。

### 4.4 时间约束
- 微信审核周期 1–3 天且不可控：**提审后先做 H5 与文档部分**，审核结果回来再补发布/回滚截图，不允许空等。
- 项目整体节奏按步骤产物推进，不按人天排期（R7）。

### 4.5 合规约束（含外部依赖与降级）
- 主体资质：个人主体 + 「工具/生活服务-预约」类目；**禁止使用需要企业资质的电商交易类目**。
- 隐私协议：用户信息、手机号、位置权限逐项声明，接入 `__usePrivacyCheck__`；实际采集项与声明必须一致（提审驳回第一大原因）。
- 域名：未备案 → 主线走云开发云函数代理；文档写清「有备案域名时切回 `request` 合法域名」的做法。
- **外部依赖硬约束（必须由用户提供/操作）**：微信小程序 AppID + 开发者工具扫码登录 + 后台提交审核权限。若用户无可用账号，C07–C09 按降级执行：只交「开发者工具本地预览 + 审核材料清单 + 模拟流程文档」，并在诚实边界如实标注「未完成真实提审/发布/回滚」，不得伪造截图。

## 5. 成功标准（判定正式交付）

1. **C01–C06、C10–C14 全部达标**（机器可验证项，以脚本/日志/DB 计数为证，不看口述）。
2. **C07–C09 至少按「真实执行」或「已声明的降级」其中之一收口**：真实执行 → 四件证据齐全；降级 → 交付包内写明降级项、原因、剩余动作清单，且 `10_交付/简历项目描述.md` 诚实边界列出。
3. 第 8.5 步安全扫描 P0/P1 清零，第 9 步用户两段式验收通过（先自由探索再对清单）。
4. `python scripts/workflow_completion_check.py <项目目录>` 全绿（10.0 门禁），`_设计实施映射表.md` 100% 映射、`_问题台账.md` 无 open/fixed 的 P0/P1。
5. 双端差异表 + 运行手册 + 验收截图集齐（设计书 M5），能支撑面试三问（两端差异 / 域名卡点 / 提审卡点）。

## 6. 主链路清单（供第 4 步按链路拆任务）

| 链路 | 输入 → 处理 → 输出 |
|---|---|
| L1 双端构建 | 一套源码 → `build:h5` / `build:mp-weixin` 条件编译 → 两套产物 + 可启动 |
| L2 登录 | 小程序 `uni.login` code / H5 账号密码 → 云函数或后端换 openid/token → 登录态（本地存储 + 请求头） |
| L3 套餐浏览 | 列表页请求 → Redis 命中/回源 MySQL → 列表渲染 + 分页/下拉刷新；详情页按 id 取单条 |
| L4 预约提交 | 表单校验 → 云函数代理 → SETNX 幂等 → 写 `booking` → publish `booking.created` → 消费者落 `notify_log` → 前端成功态 |
| L5 我的预约 | 登录态 → 按 user 查 `booking` → 状态标签渲染 |
| L6 小程序发布 | 代码上传 → 体验版 → 真机扫码 → 提审 → 审核 → 发布 → 回滚 |
