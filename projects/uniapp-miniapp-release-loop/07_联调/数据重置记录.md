## 一、重置范围

- **表**：`booking` / `notify_log` / `user` / `package`（4 张）
  - 清空联调与探针产生的预约、通知日志、openid 测试账号；`user`/`package` 一并清空后按 `db/init.sql` 重建种子。
- **Redis 键**（本机 6379，dev 无 AUTH）：
  - `ub:pkg:list`（套餐缓存）、`ub:idem:booking:*`（幂等键）、`ub:nonce:*`（签名 nonce）、`ub:jwt:blacklist:*`（登出黑名单）
  - 清理方式：`KEYS ub:*` → `DEL`；不清非本项目前缀键。
- **MQ**：`booking.notify.queue`、`booking.notify.dlq` 清空，避免消费者把已删除预约的事件写回 `notify_log`。
- **不重置**：`05_代码`/文档/截图/证据等文件产物；H5 dev 服务与后端进程保持运行；容器共享中间件（3308 MySQL / redis / rabbitmq）不重建、不误删数据卷。
- **重置方式**：含自增主键的 4 张表用 `TRUNCATE`（自增计数器归位），随后重跑 `db/init.sql`（`INSERT IGNORE` 2 账号 + 4 套餐）。
