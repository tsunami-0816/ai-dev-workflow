## 1. 技术选型说明

| 组件 | 版本 | 选型理由 | 兼容性说明 |
|---|---|---|---|
| uni-app（Vue3 + TS + Vite） | `@dcloudio/uni-app` 3.x（`vite-ts` 模板，安装时锁定 lockfile 具体版本） | 一套源码双产物（H5 + mp-weixin）是 C01 的唯一路径；Vue3 组合式 API 与 TS 类型对齐京东/伯遇 JD 的 Vue 技术栈 | 模板要求 Node ≥ 18；本机 Node 22.23 通过；Vite 5 与 uni-app 3.x 插件同源 |

| Vite | 5.x | 双端 dev/build 速度与 H5 产物 | 由 uni-app 模板锁定，不单独升级 |
| uni-ui | 1.5.x | 官方组件与 rpx 口径，减少自造组件 | 与 Vue3 版本匹配；仅用 list/swipe-action/popup 等基础件 |

| Redis | 7（共享实例 6379） | `pkg:list` 缓存（C04）+ `SETNX` 幂等键 | 共享实例，key 前缀 `ub:` 隔离 |
| RabbitMQ | 3.13（5672 / 管理台 15672） | `booking.created` → `notify_log`（C06） | 若 5672 被占用改 5673/15673，回填 `WORKFLOW_端口分配表.md` |
| Node.js 云函数 | Node 20 运行时（云端）/ 本机 22.23 模拟 | 代理后端、规避未备案域名（L2–L5 小程序端） | 双模式同一份 `handler.js`，仅 transport 不同 |
| 微信小程序 | mp-weixin（AppID `wx58cd971ff2494b89`） | C07–C09 发布闭环载体 | 个人主体 + 工具类目路线；未备案域名走云函数 |
| 测试 | pytest + Allure（C13） | 与工作流既有测试栈一致 | 只测后端 HTTP + 云函数代理层，不测小程序渲染 |

**明确不引入**：Tailwind、qiankun、Taro、React 业务代码、微信支付 SDK、短信 SDK、OSS 上传 SDK。

## 2. 整体分层架构

```
┌─ 应用层 ────────────────────────────────────────────────┐
│ H5(uni-app H5 产物 / Vite dev 5186)  │  微信小程序(mp-weixin) │
└───────────────┬───────────────────────────┬─────────────┘
                │  HTTPS/JSON                │  wx.cloud.callFunction / http
┌─ 接入层 ───────▼───────────────────────────▼─────────────┐
│ uni.request 封装(签名/超时3s/重试1次/错误码)  │  云函数 apiProxy(Node20) │
│                                              │  真实云开发 ⇄ 本机 8093  │
└───────────────┬──────────────────────────────┬──────────┘
┌─ 服务层 ───────▼──────────────────────────────▼──────────┐
│ Spring Boot 3 @8092：Auth / Package / Booking 三个 Controller │
│ 统一 code/message/data 包装 · JWT 鉴权 · HMAC 签名校验 · 限流 │
└───────┬───────────────┬───────────────┬──────────────────┘
┌─ 计算层 ───────▼──────┐ ┌─ 存储层 ───────▼──────┐ ┌─ 消息层 ─────▼─────┐
│ Service/Domain        │ │ MySQL uniapp_booking  │ │ RabbitMQ            │
│ (幂等判定/缓存编排/    │ │ (user/package/booking/│ │ booking.exchange    │
│  消息投递)             │ │  notify_log)          │ │ → notify.queue →DLQ │
│                       │ │ Redis ub:pkg:list 等  │ │ 消费者写 notify_log │
└───────────────────────┘ └───────────────────────┘ └────────────────────┘
┌─ 运维层 ─────────────────────────────────────────────────┐
│ docker compose(MySQL/Redis/RabbitMQ 复用实例) · actuator/health │
│ 日志落盘 · 启动/停止脚本 · 端口表 · 发布证据归档              │
└───────────────────────────────────────────────────────────┘
```

| 层 | 职责 | 组件 |
|---|---|---|
| 应用层 | 用户可见页面与交互（5 页 + tabBar） | uni-app Vue3 页面、Pinia store、条件编译分支 |
| 接入层 | 请求出口、协议适配、域内安全 | `request.ts`（H5 直连 8092）、云函数 `apiProxy`（小程序，双模式） |
| 服务层 | 业务编排、鉴权、契约 | Spring Boot Controller/Service、JWT Filter、签名 Filter、全局异常处理 |
| 计算层 | 幂等判定、缓存读写、消息投递与消费 | BookingService、CacheService、MQ Producer/Consumer |
| 存储层 | 持久化与缓存 | MySQL 4 表、Redis 3 类 key |
| 消息层 | 异步通知链路 | RabbitMQ exchange/queue/DLQ |
| 运维层 | 启停、健康、日志、证据 | docker compose、`/actuator/health`、`scripts/` 启停与压测脚本 |

## 3. 核心业务链路（端到端）

### L1 双端构建
| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | 一份 `src/` 源码 | `npm run build:h5` | `dist/build/h5/index.html` + assets |
| N2 | 同一份 `src/` 源码 | `npm run build:mp-weixin`（注入 `manifest.json` appid） | `dist/build/mp-weixin/app.json`（pages=5）+ 分包资源 |
| N3 | 产物 | 校验脚本 `scripts/check_build.mjs` | C01 证据：两目录存在 + app.json 页数=5 |

### L2 登录
| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | 小程序端 `uni.login` code | 云函数 `apiProxy` action=`login` | 调 `code2session`（AppID/AppSecret 取自环境变量）→ openid |
| N2 | openid | 后端 `POST /api/auth/login`（HMAC 签名 + 时间戳） | `user` 表 upsert → 签发 JWT（HS256，2h） |
| N3 | token | 前端存 `uni.storage`，请求拦截器注入 `Authorization` | 登录态可用（C02 路径起点） |
| H5 分支 | 账号密码（demo/welcome1） | 同上接口，`openid=null`、`account` 字段 | 同一 JWT 体系 |

### L3 套餐浏览
| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | 列表页 page/size | 查 `ub:pkg:list:{page}:{size}` | 命中 → 直接回（C04 分子） |
| N2 | 未命中 | 查 `package` 表 `status=1`，按 `sort` 排序 | 回源结果写回 Redis（TTL 300s），返回 |
| N3 | 详情页 id | `ub:pkg:detail:{id}` → 回源 `package` | 单条套餐 + 标签 + 轮播图数组 |
| N4 | 前端 | 分页追加 + 下拉刷新（`onPullDownRefresh` 重置到第 1 页） | 列表渲染；375/414 无横向溢出（C10） |

### L4 预约提交
| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | 表单（packageId/date/slot/contact/remark） | 前端校验（必填、手机号 11 位、日期≥今天） | 校验失败的字段级提示，不发请求 |
| N2 | 合法表单 | 云函数代理（签名、3s 超时、失败重试 1 次带同一 `X-Idempotency-Key`） | 转发 `POST /api/bookings` |
| N3 | 请求 | 后端：`SETNX ub:idem:booking:{phone}:{date}:{slot}` TTL 600s | 已存在 → `42901` 重复提交，前端提示「已提交过」 |
| N4 | SETNX 成功 | 写 `booking`（唯一索引二次兜底） | bookingId |
| N5 | 写库成功 | publish `booking.created`（payload: bookingId/openid/packageId/slot） | 消费者 `@RabbitListener` 落 `notify_log` |
| N6 | 响应 | `code=0, data={bookingId, status}` | 前端跳「我的」并高亮新单 |

### L5 我的预约
| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | 登录态 | `GET /api/bookings`（JWT 取 userId） | 按 `created_at desc` 返回本人预约 |
| N2 | 列表 | 前端状态映射（0 待确认 / 1 已确认 / 2 已取消） | 状态标签渲染 + 空态 |

### L6 小程序发布
| 节点 | 输入 | 处理 | 输出 |
|---|---|---|---|
| N1 | mp-weixin 产物 + `project.config.json` | 微信开发者工具「上传」 | 开发版本 + version 号 |
| N2 | 开发版本 | 设为体验版 + 添加体验成员 | 体验版二维码（C07） |
| N3 | 真机扫码 | 走 L2–L5 主链路 | 真机截图 ×2（首页 / 我的） |
| N4 | 后台提审 | 版本描述 + 页面截图 + 测试账号 | 提审记录（C08） |
| N5 | 审核结果 | 通过 → 全量发布；驳回 → 整改 → 二次提审 | 线上版本号 + 时间（C09） |
| N6 | 已发布 | 后台「版本回退」到上一版本 | 回滚前后版本号 + 截图（C09） |

## 5. 数据模型设计

database：`uniapp_booking`（共享 MySQL 8 实例 3310，独立库）

```sql
CREATE TABLE `user` (
  `id`         BIGINT       NOT NULL AUTO_INCREMENT,
  `openid`     VARCHAR(64)  DEFAULT NULL COMMENT '小程序 openid，H5 账号为 NULL',
  `account`    VARCHAR(32)  DEFAULT NULL COMMENT 'H5 demo 账号',
  `phone`      VARCHAR(20)  DEFAULT NULL,
  `nickname`   VARCHAR(64)  DEFAULT NULL,
  `created_at` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_openid` (`openid`),
  UNIQUE KEY `uk_account` (`account`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `package` (
  `id`        BIGINT       NOT NULL AUTO_INCREMENT,
  `title`     VARCHAR(64)  NOT NULL COMMENT '套餐名，如「城市轻写真」',
  `price`     DECIMAL(10,2) NOT NULL,
  `cover_url` VARCHAR(255) NOT NULL,
  `tags`      VARCHAR(128) NOT NULL COMMENT '逗号分隔：室内,2套服装,精修8张',
  `summary`   VARCHAR(512) DEFAULT NULL,
  `sort`      INT          NOT NULL DEFAULT 0,
  `status`    TINYINT      NOT NULL DEFAULT 1 COMMENT '1 上架 0 下架',
  `created_at` DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_status_sort` (`status`,`sort`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `booking` (
  `id`          BIGINT       NOT NULL AUTO_INCREMENT,
  `user_id`     BIGINT       NOT NULL,
  `package_id`  BIGINT       NOT NULL,
  `book_date`   DATE         NOT NULL,
  `slot`        VARCHAR(16)  NOT NULL COMMENT '上午/下午/晚间',
  `contact`     VARCHAR(20)  NOT NULL COMMENT '联系人手机号，幂等键',
  `remark`      VARCHAR(255) DEFAULT NULL,
  `status`      TINYINT      NOT NULL DEFAULT 0 COMMENT '0 待确认 1 已确认 2 已取消',
  `created_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_contact_date_slot` (`contact`,`book_date`,`slot`),
  KEY `idx_user_created` (`user_id`,`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `notify_log` (
  `id`          BIGINT      NOT NULL AUTO_INCREMENT,
  `booking_id`  BIGINT      NOT NULL,
  `event`       VARCHAR(32) NOT NULL DEFAULT 'booking.created',
  `payload`     VARCHAR(1024) DEFAULT NULL,
  `consumed_at` DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_booking_event` (`booking_id`,`event`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

索引与约束理由：

- `uk_contact_date_slot`：C05 幂等的**最终防线**（Redis SETNX 失效或重启后仍不重复）。
- `uk_booking_event`：消费者重复投递只落 1 条，保证 C06 计数不被重复消费污染。
- `idx_user_created`：L5 按用户倒序查单，避免全表扫。
- 字段规范：主键 BIGINT 自增；时间统一 DATETIME 本地时区（Asia/Shanghai）；金额 DECIMAL 不用 float；中文注释必填。

Redis key（前缀 `ub:` 隔离共享实例）：

| key | 类型 | TTL | 用途 |
|---|---|---|---|
| `ub:pkg:list:{page}:{size}` | string(JSON) | 300s | 套餐列表缓存（C04） |
| `ub:pkg:detail:{id}` | string(JSON) | 300s | 详情缓存 |
| `ub:idem:booking:{phone}:{date}:{slot}` | string | 600s | SETNX 幂等键 |

## 6. 接口规范定义

### 6.1 统一请求/返回

请求头：

```
Content-Type: application/json
Authorization: Bearer <JWT>            # 除登录外必带
X-Sign: HMAC-SHA256(rawBody + "|" + X-Timestamp, APP_SECRET)
X-Timestamp: 1710000000                 # 秒，±60s 内有效
X-Idempotency-Key: <uuid>               # 写接口建议带
```

返回体（HTTP 200 承载业务结果；鉴权/签名失败用 401）：

```json
{ "code": 0, "message": "ok", "data": { }, "traceId": "b3f1c0..." }
```

### 6.2 错误码

| code | HTTP | 含义 | 前端处理 |
|---|---|---|---|
| 0 | 200 | 成功 | — |
| 40001 | 400 | 参数校验失败（附 `data.field`） | 字段级红字 |
| 40101 | 401 | 未登录 / token 过期 | 清登录态 → 跳登录页 |
| 40102 | 401 | 签名校验失败 | toast「请求非法」 |
| 40301 | 403 | 越权访问（访问他人资源） | toast + 返回 |

| 50001 | 500 | 服务异常 | toast「服务开小差了」 |
| 50002 | 504 | 上游/云函数超时 | toast「网络不稳定，请重试」 |

### 6.3 核心接口清单

| # | 方法 | 路径 | 鉴权 | 入参 | 出参 data |
|---|---|---|---|---|---|
| 1 | POST | `/api/auth/login` | 否（签名必带） | `{openid?, account?, password?, nickname?}` | `{token, expiresIn, userId}` |
| 2 | GET | `/api/packages` | 否 | `?page=1&size=10` | `{list[], total, page, size}` |
| 3 | GET | `/api/packages/{id}` | 否 | path id | `{id,title,price,coverUrl,tags[],summary,status}` |
| 4 | POST | `/api/bookings` | 是 | `{packageId,bookDate,slot,contact,remark}` | `{bookingId,status}` |
| 5 | GET | `/api/bookings` | 是 | `?page=1&size=10` | `{list[{id,packageTitle,bookDate,slot,status}], total}` |

### 6.5 云函数约定的内部协议

```json
// 请求（前端 → 云函数）
{"action":"packages|packageDetail|login|createBooking|myBookings","payload":{...},"ts":1763500000,"sign":"..."}
// 返回（云函数 → 前端）
{"code":0,"message":"ok","data":{...},"traceId":"cf-...","elapsedMs":210}
```

云函数职责：参数白名单校验 → 组装备注查询串/请求体 → HMAC 签名 → 调后端（超时 3s，非 2xx 或超时重试 1 次）→ 统一映射错误码 → 记 `elapsedMs`（C03 取样来源）。

### 7.1 本机（开发/验收）拓扑

### 7.3 环境划分与高可用

### 12.3 字体与排版

- 标题：思源宋体 Semibold **600**，34px / 行高 1.3 / 字距 +0.02em。
- 正文标签：思源黑体 Regular **400**，15px / 行高 1.7。
- 档期·价格·编号：等宽数字 500，18px，`tabular-nums`。
- 只用 400/600 两档字重做层级；中文禁斜体；禁 0.12em 以上的伪高级拉宽。

### 12.4 布局与间距

- 圆角：照片 `0px`、按钮/标签 `2px`，全页不出现 ≥4px 圆角。
- 间距基网 8px，档位 `8/16/24/40/64`；左右边距 24px（375 基准）；区块间 64px；清单行高 72px，用 1px 细线分隔而非卡片间距。
- 触控目标 ≥44×44；照片只向右出血，不居中对称；单列纵向无横向滑动。
- 375×812 分区：眉批 12% / 门面 46% / 清单 30% / 留白 12%。

### 12.5 动效（motion-web，强度 3）

仅两处：① 细线从左向右「曝光」铺开 480ms `cubic-bezier(.2,.7,.3,1)`；② 点击清单行价格数字 300ms 跳动。`prefers-reduced-motion` 全退化为终态。

### 12.6 明确「不做什么」

紫蓝渐变、发光/霓虹、玻璃拟态、卡片套卡片、三等分特性卡、居中 Hero + 渐变大标题、≥16px 圆角白卡海、emoji 图标、满屏 fade-up、hover 抬升阴影、视差粒子、噪点铺满、`transition: all`、无 reduced-motion 的入场动画。
