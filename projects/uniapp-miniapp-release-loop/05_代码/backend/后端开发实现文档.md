## 4. 接口定义

统一响应：`{code,msg,data}`；成功 `code=0`。HTTP 状态与 code 对应见 `GlobalExceptionHandler`。

| # | 方法 | 路径 | 鉴权 | 入参 | 出参 data | 失败码 |
|---|---|---|---|---|---|---|
| 1 | POST | `/api/auth/login` | 否 | `{account?,password?,openid?,nickname?}` | `{token,expiresIn,userId,nickname}` | 40001（两形态都缺）、40101（账号/口令错） |
| 2 | POST | `/api/auth/logout` | JWT | Header `Authorization` | null | 40101/40103 |
| 3 | GET | `/api/packages` | 否 | `?page=1&size=10` | `{list[],total,page,size}` | — |
| 4 | GET | `/api/packages/{id}` | 否 | path id | `{id,title,price,coverUrl,tags[],summary,status}` | 40401 |
| 5 | POST | `/api/bookings` | JWT | `{packageId,bookDate,slot,contact,remark}` | `{bookingId,status,duplicated}` | 40001（字段/时段非法）、40002（日期越界）、40401、50001 |
| 6 | GET | `/api/bookings` | JWT | `?page=1&size=10` | `{list[{id,packageId,packageTitle,bookDate,slot,contactMasked,status,statusText,createdAt}],total,page,size}` | 40101 |

**MQ（T-403/404）**：`booking.exchange`(direct) → `booking.notify.queue`（routing key `booking.created`）→ 重试 3 次 → `booking.dlx` → `booking.notify.dlq`。
消息体为 `BookingCreatedEvent` JSON（手机号脱敏）；消费者 `INSERT IGNORE notify_log` 幂等。生产端 `publisher-confirm-type: correlated`，同步等 confirm 3s。

错误码实现（`common/ErrorCode.java`）：40001/40002/40101/40102/40103/40301/40400/40401/42901/50000/50001/50002。
> 说明：架构 §6.2 的 8 码为基线；40002（日期越界）、40103（token 过期）、40400（未知路径）、40401（套餐不存在）、50000（未知异常兜底）为落地补充，已在映射表 D-23 行登记。
> 40301 保留码位但当前无触发路径：越权防护靠「服务端忽略客户端 userId + 按 JWT 过滤」，不通过读他人 id 再拒绝的方式实现。

### 云函数（T-206 / D-16 / D-17）

`05_代码/cloud-functions/`，零第三方依赖（Node 内置 `http/https/crypto`）。同一份 handler 供两个入口：

| 入口 | 文件 | 场景 |
|---|---|---|
| 本机 http（8093） | `apiProxy/localServer.js` | 无云开发环境 / 开发者工具联调（需勾「不校验合法域名」） |
| 云开发 | `apiProxy/index.js`（`exports.main`） | 开通云开发后 `wx.cloud.callFunction`（代码同源，未真机验证，见 §6） |

前端 → 云函数统一 event：`{action, payload, token}`（`token` 为裸 JWT）。action 白名单：

| action | 后端接口 | payload 允许字段 | 需 token |
|---|---|---|---|
| packages | `GET /api/packages` | `page`(1~1000,默认1)、`size`(1~50,默认10) | 否 |
| packageDetail | `GET /api/packages/{id}` | `id` 正整数 | 否 |
| login | `POST /api/auth/login` | `account`+`password` 或 `openid`；`nickname` 可选 | 否 |
| logout | `POST /api/auth/logout` | 无 | 是 |
| createBooking | `POST /api/bookings` | `packageId`、`bookDate`、`slot`(上午/下午/晚间)、`contact`、`remark`(≤255) | 是 |
| myBookings | `GET /api/bookings` | `page`、`size` | 是 |

约束：未知 action / 未知字段 → 40001（不把越权参数透给后端）；每次尝试生成新 `X-Nonce`；单次 3s 超时、网络/超时/5xx 重试 1 次；
重试耗尽 → 50002「网络不稳定，请重试」；请求体上限 1MB；响应 `{code,msg,data,traceId,elapsedMs}`。
`getOpenid`：`code` → `sns/jscode2session` → 只回 `openid/unionid`，`session_key` 不返回前端；缺 `MP_APPSECRET` 明确 50001，不伪造 openid。

## 6. 与架构的偏差登记（5.5 Review 重点）

| 项 | 架构原文 | 实际 | 原因 / 处置 |
|---|---|---|---|
| MySQL 端口 | 3310 | 3308（Docker `rag-mysql`）；**2026-11-20 5.5 返工改用 3307（Windows 原生 MySQL 8.0）** | 3310 容器未运行；返工时 Docker Desktop 未启动、3308 无监听，改在 3307 上 `init.sql` 建库（4 表/4 套餐/2 账号，UTF-8 中文回读正常）。库名/表结构不变，`MYSQL_PORT` 可切回 |
| Redis | 6379（共享） | 6379（Windows 原生 redis 5.0.14.1，无 AUTH） | 同名端口被本机实例占用；dev 专用，8.5 安全扫描需复核 |
| `user` 表 | 无口令列 | 增 `password_hash`（PBKDF2） | L2 要求 H5 账号登录，架构 §5 漏列；属 schema 变更（关键），5.5 复核 |
| HMAC 适用范围 | 6.1 写「登录也签名必带」 | H5 直连不带签名；`X-Client:cloud` 或出现任一签名头时强制校验 | 浏览器不能持有 APP_SECRET；云函数通道全量校验，H5 通道匿名 |
| openid 登录来源 | — | **`AuthService.login(req, verifiedCloud)`：带 openid 的登录必须 `verifiedCloud=true`，否则 40102** | Q-004：5.5 实测 H5 直连可凭任意 openid 建号。`SignatureFilter` 验签通过后写 request 属性 `ub.verifiedCloud`，H5 无签名置 false；账号口令通道不受影响 |
