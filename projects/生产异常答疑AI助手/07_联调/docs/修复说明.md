## 1. 问题 T-01：数组型响应被整包漏读，造成 7 项假失败

**修改点**：`payload()` 函数（原第 68–74 行）

**修改影响分析**

| 项 | 内容 |
|---|---|
| 涉及文件 | `07_联调/e2e_lian_tiao.py`（仅此一个文件，不触碰 `05_代码/` 任何产品代码） |
| 涉及函数 | `payload()`，被 L1–L11 全部断言间接调用 |
| 可能影响的其他链路 | 无产品链路影响；仅影响本脚本对响应的解析正确性。改为「只要存在 `data` 键就解壳」后，对既有 dict 型响应（notifications / tickets / eval 的 `{list,total}` 结构）行为不变 |
| 风险点 | 若某接口 `data` 恰为 `null`，`payload()` 返回 `None`，调用处 `.get()` 会 AttributeError。已核对：本轮所有断言涉及的接口在成功路径下 `data` 均非 null；失败路径由 `req()` 返回 `(status, body)`，断言先看 status |

**修改后代码片段**

```python
def payload(body):
    """剥掉统一响应外壳 {code,message,data}。
    注意 data 既可能是 dict，也可能是 list（documents/knowledge/handlings/conversations/messages
    这几个接口直接返回数组），只按 dict 判断会把数组整包漏掉、误读成空列表。"""
    if isinstance(body, dict) and "data" in body:
        return body["data"]
    return body
```

1. 重跑脚本第 2 轮，原本 FAIL 的 L2-2 / L3-2 / L3-3 / L5-4 / L6-1 / L6-2 / L6-3 全部 PASS。
2. 交叉验证：脚本内 L10 直接查 SQLite——`document` 表 5 份 indexed、`knowledge_archive` 2 条 approved、`ticket_handling` 3 条，证明数据真实存在，首轮确为读错。
