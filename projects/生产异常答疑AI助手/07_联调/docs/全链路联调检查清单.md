## 2. 严重等级划分

- **P0 阻塞**：核心业务链路完全中断、主流程走不通（如登录失败、提问 500、派单不落库）。
- **P1 严重**：核心链路部分异常、关键数据不一致（如工单通知缺失、沉淀未生成、越权可访问）。
- **P2 一般**：非核心链路异常、交互瑕疵（留档至「待优化建议」，本轮不修）。

## 3. 本轮自动化执行说明

`e2e_lian_tiao.py` 用真实 HTTP 调后端接口（自带 token、multipart 上传、断言 401/403 等状态码），并直接查 SQLite 做一致性核对，覆盖 L1–L11 共 40+ 条断言。逐条 PASS/FAIL 与证据见执行日志；未能通过的项汇总进《全链路联调问题清单》。

## 4. 未覆盖场景（本轮不测，登记留档）

1. **前端页面级交互**：Streamlit 页面渲染、按钮点击、会话切换、上传控件等 UI 行为未做自动化（第 6 步阶段二已人工验证主流程，第 9 步验收再走人工全量走查）。
2. **扫描件 PDF / OCR 链路**：本机未装 Tesseract + poppler，扫描件上传按预期报错，未见成功路径。
3. **模型质量类断言**：分级是否「分级得准」、答案是否「答得对」取决于 3B 小模型，仅做链路断言（字段合法、来源非空），不做语义正确性判定。
4. **并发与性能**：多用户并发提问、检索耗时压测未做（属第 8 步/后续性能专项）。
5. **沉淀命中（L6-3）**：受小模型检索质量影响，仅做弱断言，若未命中按待确认登记而非判 P0。
6. **云端模型 provider 切换**（`MODEL_PROVIDER=api`）未验证，本轮只用本地 Ollama。
