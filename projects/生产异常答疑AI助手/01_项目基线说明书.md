## 1. 项目核心目标

### 1.1 要解决的核心问题

中小制造工厂的生产现场，遇到**设备故障、工艺异常、安全规范**三类问题时存在：

- **依赖个人经验**：答案掌握在少数老员工脑中，人员流动即知识流失；
- **查手册慢**：新员工在纸质/电子手册中定位条款耗时，平均约 15 分钟才能获得一次有效解答；
- **跨部门沟通低效**：问题该不该找维修、找工艺、找谁，路由不清，反复转述；
- **经验未沉淀**：每次处理完的故障没有结构化归档，同类问题反复发生、重复求助。

### 1.2 解决方案

基于工厂**现有生产手册、设备说明书、历史故障记录**，搭建一个「RAG 答疑 + 异常分级派单 + 知识沉淀」的 AI 助手，形成闭环：

```
自然语言提问 → 知识库检索增强生成答案（带来源条款/历史方案/操作步骤）
            → 轻量 Agent 判断问题等级
               ├─ 简单问题：直接给出答案
               └─ 复杂问题：自动生成工单 → 推送给维修/工艺负责人 → 处理并反馈
            → 已解决问题归档 → 补充进知识库 → 可被再次检索
```

### 1.3 业务价值

- 一线简单异常「秒级自助解决」，降低对老员工的依赖；
- 复杂异常路由到正确负责人，减少跨部门转述成本；
- 处理结果结构化沉淀，形成可复用、可检索的组织知识资产；
- 以低成本 MVP 验证「RAG + 轻量 Agent」在工厂场景的真实效果，成果可量化、可写入简历。

## 3. 项目范围界定

### 3.1 核心范围（必须做，决定 MVP 成立）

1. **知识库构建与管理**：导入 1–2 份真实设备手册/生产规范；文档解析（**文字版优先，兼容扫描件 OCR**）、切分、向量化、入库；支持文档上传、重建索引、**删除文档（同步清理向量）**。
2. **RAG 知识库问答**：自然语言提问；检索增强生成；返回**手册条款、历史解决方案、分步操作步骤**；答案附来源引用；**支持多轮追问（携带会话上下文）**。
3. **异常分级派单（轻量 Agent）**：识别问题等级；简单问题直接答；复杂问题自动生成工单（含问题描述、等级、建议负责人类型），**并通过系统内通知（未读角标）推送给对应维修/工艺负责人**。
4. **工单流转与结果反馈**：工单列表、状态流转（待处理→处理中→已解决/已关闭）、负责人填写处理结果、提问人可查看反馈。
5. **知识沉淀**：已解决（含工单处理结果）的问题一键/自动归档，结构化补充进知识库，可被再次检索。
6. **场景与效果验证**：3 类场景、≥ 50 条异常的需求清单与黄金测试集；输出 MVP 测试报告（M3/M4/M5/M7 实测）。
7. **登录与角色权限（最简）**：用户名 + 密码登录、登录态保持；按员工 / 维修 / 工艺 / 管理员四类角色控制可见页面与可执行动作（提问、领单处理、知识库管理与审核）。
8. **多轮会话管理**：会话列表、历史消息、在同一话题内连续追问，系统结合最近若干轮上下文作答。

### 3.2 配套范围（辅助做，服务于产品完整性与求职演示）

- 1 份需求文档（需求清单 + 优先级）；
- 1 套完整业务流程图（提问→答案匹配→工单流转→结果反馈→沉淀）；
- 15 页高保真产品原型；
- 简单的 Web 端界面（问答页、工单页、知识库管理页）；
- 答案反馈机制（有用/无用、点踩理由），用于沉淀与评估。

### 3.3 排除范围（本 MVP 明确不做）

- 不与工厂真实 MES/ERP/WMS/IoT/设备控制系统做对接，数据用示例/导入方式模拟；
- 不做对设备的自动控制或现场自动执行动作，Agent 只「答疑 + 派单 + 归档」，不直接操作设备；
- 不做多 Agent 协作、复杂工作流引擎、模型训练/微调（只用现成开源模型或通用 API）；
- 不做完整的多租户、组织架构、SSO 单点登录与复杂 RBAC 权限矩阵，仅实现**最简用户名 + 密码登录与四类角色（员工/维修/工艺/管理员）**；
- 不做生产级高可用、高并发、分布式、容器集群等部署（单机本地可跑即可）；
- 不做原生移动 App、不做语音/图片/图纸识别等多模态（MVP 仅文本）；
- 不做企业级 IM（钉钉/企微/飞书）真实推送集成，派单以系统内工单/列表通知为主，可留模拟推送接口。

## 4. 约束条件

| 类别 | 约束 |
|---|---|
| 技术栈约束 | 开源 RAG 框架（**LangChain** 生态）；大模型为「开源大模型（本地）或通用大模型 API」二选一或可切换；实现语言 Python；向量库、前端、存储均选 MVP 可快速落地的轻量方案（具体选型在第 2 步） |
| 部署环境约束 | 能在**单台普通 PC（Windows）本地运行**，不依赖大规模云资源；需考虑工厂资料涉密场景，支持私有化/离线本地运行的可能 |
| 资源约束 | 产品经理 1 人可独立完成从需求到 MVP 验证；无专职后端/前端团队；仅需 1–2 份真实手册/规范；硬件为普通笔记本（无独立高性能显卡时需可降级到 CPU 小模型或云端 API） |
| 时间约束 | 以完成「可演示 MVP + 验证报告」为目标，原始描述未给具体截止日期；具体排期与任务工期在第 4 步任务拆解中确定，**不在此臆造日期** |
| 合规约束 | 工厂手册/故障记录可能涉密，须支持本地/私有化部署、数据不外传；模型不得臆造安全规范（安全类答案必须有手册来源并标注「以手册为准/必要时联系负责人」）；个人/企业数据最小化使用 |

## 5. 成功标准（上线/交付判定，逐条可核对）

- [ ] **S1 闭环可演示**：提问 → 检索问答（带来源）→ 复杂问题分级派单 → 工单流转 → 负责人反馈 → 问题归档 → 再被检索，全链路在本地可完整走通。
- [ ] **S2 覆盖达标**：覆盖设备故障、工艺异常、安全规范 3 类场景；需求清单与测试集 ≥ 50 条异常。
- [ ] **S3 资料落地**：成功导入 1–2 份真实设备手册/生产规范，并能就其内容有效问答（M8）。
- [ ] **S4 效果达标**：黄金测试集答疑准确率 ≥ 85%（M4）；简单问题端到端响应实测记录，目标 ≤ 30 秒（M3）。
- [ ] **S5 派单与沉淀**：复杂问题分级路由准确率 ≥ 85%（M5）；归档条目可被再次检索（M7）。
- [ ] **S6 可溯源**：所有答案附来源，安全类问题 100% 有手册依据、无臆造（M9）。
- [ ] **S7 产品交付物齐全**：1 份需求文档、1 套业务流程图、15 页高保真原型、1 份 MVP 测试报告。
- [ ] **S8 可独立运行**：产品经理按部署说明在普通 PC 上即可安装、启动、复现演示，不依赖开发人员在场。
