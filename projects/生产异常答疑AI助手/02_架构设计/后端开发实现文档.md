# 后端开发实现文档

> 对应《第二轮技术架构设计文档》。FastAPI + LangChain + Chroma + SQLite，本地 Ollama / 云端 API 可切换。

## 1. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| Web 框架 | FastAPI 0.115+ | 自动 OpenAPI 文档 `/docs` |
| ORM | SQLAlchemy 2.0 | SQLite，`check_same_thread=False` |
| RAG | LangChain 0.3 + langchain-openai | 本地/云端均走 OpenAI 兼容接口 |
| 向量库 | Chroma 0.5 | 持久化到 `./data/chroma` |
| Embedding | BAAI/bge-small-zh-v1.5（本地 CPU） | 可切云端 text-embedding-v3 |
| 分词 | jieba | BM25 中文分词 |
| 认证 | JWT (HS256) + passlib bcrypt | 1440 分钟过期 |
| 文档解析 | pypdf / docx2txt / pytesseract+pdf2image | 文字版优先，扫描件 OCR |

## 5. RAG 核心流程

```
用户提问
  │
  ├─ 1. 多轮上下文：取 conversation 历史（最近 6 轮）
  │
  ├─ 2. 异常分级（rag/grading.py）
  │     ├─ 安全关键词前置 → 强制 P0 派 safety
  │     ├─ LLM 结构化输出 JSON（GradingResult）
  │     ├─ 三级兜底：解析失败→重试→正则提取→默认派单
  │     └─ 低置信兜底：confidence<0.6 且模型说"简单"→转派单
  │
  ├─ 3A. need_ticket=true → 自动派单
  │     ├─ 生成工单 T{date}-{seq}
  │     ├─ 按 route_type 通知对应角色全部用户
  │     └─ 返回工单号 + 建议检查项
  │
  └─ 3B. need_ticket=false → RAG 问答（rag/chains.py）
        ├─ 混合检索（rag/retriever.py）
        │   ├─ 向量检索：Chroma，top_k=8，可按 scenario 过滤
        │   ├─ BM25 检索：jieba 中文分词，top_k=8
        │   ├─ EnsembleRetriever 加权合并（向量 0.6 / BM25 0.4）
        │   └─ 去重后取 ensemble_top_k=4
        ├─ 受约束生成（rag/prompts.py）
        │   ├─ 只依据参考资料，禁止编造
        │   ├─ 结论→分步操作→来源（文档名+页码）
        │   └─ 无相关内容→明确拒答并转派单
        └─ 提取步骤（数字编号）、来源列表
```

### 文档入库流程
```
上传 PDF/Word
  → pypdf/docx2txt 提取文字（按页/段）
  → 文字过少(<80字符)→ 判定扫描件 → pytesseract(chi_sim+eng)+pdf2image OCR
  → RecursiveCharacterTextSplitter 切分（500字符/50重叠，中文分隔符优先）
  → bge-small-zh 向量化 → Chroma 持久化（metadata 含 doc_id/doc_name/page/scenario/source_type）
```

## 6. 工单状态机

```
pending ──领取(assign)──> processing ──关闭(close)──> closed
                              │
                              └──处理记录(handle)──> processing（可多次）
```
- 非法流转返回 `ERR_INVALID_TRANSITION (4002)`
- 关闭时 `archive=true` 自动创建 knowledge_archive（status=pending），admin 审核通过后向量化入库

## 9. 错误码

| 区间 | 含义 | 示例 |
|---|---|---|
| 1000 | 参数/认证 | 1001 参数错误、1004 未认证、1005 无权限、1006 不存在 |
| 2000 | 检索/知识库 | 2001 知识库空、2002 无相关内容 |
| 3000 | 模型/Agent | 3001 模型不可用、3002 分级解析失败 |
| 4000 | 工单 | 4001 工单不存在、4002 状态非法流转 |
| 5000 | 系统 | 5001 内部错误、5003 下游失败 |

统一响应：`{code, message, data, trace_id}`，HTTP 状态码与 code 分离。

## 10. 启动与验证

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 本地模型（可选，省钱方案）
ollama pull qwen2.5:3b-instruct-q4_K_M

# 3. 初始化数据库与种子账号
python scripts/init_db.py

# 4. 启动
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload

# 5. 离线评估（需模型可用）
python eval/run_eval.py
```

冒烟主流程：employee 登录 → admin 上传手册 → employee 简单提问（带来源答案）→ 追问 → 复杂问题触发派单 → repair 收到通知 → 领取/处理/关闭（勾选沉淀）→ admin 审核入库 → 相似问题再问命中。
