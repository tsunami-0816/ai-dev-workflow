# 从 0 到 1 项目自动工作流 · 使用说明

这套文件把你那份《项目自动流程.docx》变成了一个**在豆包对话里能直接驱动的自动工作流**。你不用再手动一步步复制提示词，只要说一句话，我就按固定流程往下做；需要你亲自操作的地方，我会停下来明确告诉你做什么。

## 二、怎么启动一个新项目（一步一步照做）

**第 1 步**：在对话框里直接发我：

> 启动新项目：<项目名>
> （然后把你的原始项目描述完整发我：要做什么系统、用什么技术栈、部署环境、时间要求等）

**第 2 步**：我会自动复制项目模板、建好文件夹，然后从第 1 步「项目基线定义」开始做，依次产出基线说明书、架构设计、评审报告、任务拆解、前后端代码……每完成一份文档我都会存到项目对应编号的文件夹里。

**第 3 步**：遇到下面 3 个「人工卡点」，我会主动停下，等你操作，不会假装帮你做完：

| 卡点 | 你要做的事 |
|---|---|
| 👤 第 3 步 架构评审 | 看一眼架构：技术选型你电脑能不能装、版本冲不冲突、有没有漏掉模块，回复「可以继续」或贴出问题 |
| 👤 第 6 步 本地冒烟 | 按我给的命令在你电脑上装依赖、启动服务、走一遍核心流程，**把终端报错完整贴给我** |
| 👤 第 9 步 最终验收 | 按验收清单在本地完整点一遍，把每条「通过/不通过、实测结果」回填给我 |

**第 4 步**：平时你只要发：

- 「继续」或「继续下一步」——我读进度看板往下做；
- 「这是报错：……」——我按真实报错给你完整改法（第 6 步起的修复都基于真实报错，不瞎猜）；
- 「人工检查通过，继续」——解除当前卡点。

## 三、几条我会严格遵守的铁律（你也可以用它监督我）

1. **卡点不跳过**：架构评审、本地冒烟、最终验收，必须你亲自确认，我不替你下结论。
2. **Bug 只修 3 轮**：全量测 1 轮 + 修复回归最多 2 轮，超限要么回流架构、要么留到下版本，不无限返工。
3. **不超范围**：修 Bug 时只改清单里的问题，绝不顺手重构、绝不改正常运行的代码。
4. **前后端并行**：后端先出 Mock 数据，前端基于 Mock 同步开发，节省时间。
5. **真实报错优先**：第 6 步之后所有修复都基于你本地真实跑出来的报错和截图。
6. **上下文不膨胀**：每步只带必要的上游材料（附录 B 规则），历史决策沉淀在文档和进度看板里，所以即使对话变长或重新开对话，我读 `_项目状态.md` 就能接着干，不会重做。

---

## 四、进度怎么查

每个项目根目录有一份 `_项目状态.md`，随时记录：当前走到第几步、各步产物在哪、修复循环用了几轮、现在卡在哪、需要你做什么、遗留了哪些 P2/P3 问题。你打开它就能看到项目全貌。
