# 工作流冗余清理与闸门修复方案（2026-11-11）

> 依据：2026-11-11 全仓盘点。基线校验结果：`wf steps --check` 全绿（29 个步骤 / 27 条规则 / 21 项门禁产物），`pytest scripts/tests -q` 31 passed。
> 本方案只修“已有定义但没落地”和“重复维护”的地方，**不新增步骤、不新增规则、不改 10.0 门禁的判据结构**。

---

## 0. 修复原则

1. **只补落点，不加概念**：每条改动都对应现有步骤、现有脚本或现有文档，不引入新步骤 id、新规则编号。
2. **历史项目不追溯**：新增产物一律用 `launch_date`（或看板「创建日期」）豁免旧项目，禁止用“清空 artifacts”代替豁免。
3. **机器判据可回归**：每个修复都配一条可执行验证，优先加进 `wf steps --check` 或 `pytest scripts/tests`。
4. **小批次提交**：每批一个 commit，可单独 `git revert`，不把“清理”和“行为变更”混在同一次提交里。

### P0-4 修正 6.5 / F2 的“前后端适用条件”

**现状**：
- `steps.yaml` 中 `06.5_契约/openapi.json` 标 `requires_frontend: true`，纯后端 HTTP 服务被跳过；
- `F2_体检/前端UI质量报告.md` 没有任何条件标记，纯后端翻新项目反而必须交 UI 报告。

**改动 1：新增 `requires_http_api` 语义**（`workflow_completion_check.py`）

```python
def _has_http_api(project_root: Path) -> bool:
    """看板「接口形态」为二进制/非 HTTP 时返回 False；缺失默认 True（保守要求）。"""
    board = project_root / "_项目状态.md"
    if not board.exists():
        return True
    text = board.read_text(encoding="utf-8", errors="ignore")
    if re.search(r"接口形态\*{0,2}[：:]\s*(二进制|非\s*HTTP|Protobuf|KCP|WebSocket-only)", text):
        return False
    return True
```

在 `check_one()` 的 `requires_frontend` 分支旁增加：

```python
if item.get("requires_http_api") and not _has_http_api(project_root):
    result.update(status="OK", skipped="看板接口形态非 HTTP，无 OpenAPI 可导出，跳过",
                  details="同上")
    return result
```

**改动 2：`steps.yaml`**

```yaml
# 6.5
- path: 06.5_契约/openapi.json
  requires_http_api: true      # 替代原来的 requires_frontend
# F2
- path: F2_体检/前端UI质量报告.md
  requires_frontend: true      # 新增
```

**改动 3：看板模板** `projects/_TEMPLATE_新项目/_项目状态.md` 增加一行：

```
- **接口形态**：HTTP
```

取值枚举：`HTTP | 二进制 | 非HTTP`，缺省按 HTTP 处理。

**验证**：
- 新建 fixture 看板写 `接口形态：二进制` → OpenAPI 判 `OK + skipped`；
- 写 `接口形态：HTTP` 或去掉该行 → 缺 `openapi.json` 判 `MISSING`；
- 翻新 fixture 写 `本项目无前端` → F2 UI 报告判 `OK + skipped`。
