## 四、运维优化流程设计

### 4.1 唤起口令

「优化」→ 触发下列四阶段流程。step11 自迭代是这个流程的特例（项目结束时自动触发）。

### 4.2 四阶段流程

```
┌──────────────────────────────────────────────────────────────────┐
│ 1️⃣ 汇总问题                                                      │
│   source A: WORKFLOW_改进建议.md 里状态不是「已归档」的条目        │
│   source B: WORKFLOW_规则体检台账.md 里连续 2 项以上未触发的活跃规则│
│   source C: 用户对话里近期提到的痛点（本轮你说的「优化」本身）     │
│   输出：本轮问题清单（按优先级排序）                               │
│                                                                  │
│ 2️⃣ 出方案（不马上改！）                                          │
│   每条问题 → 改什么 / 改法 / 落点（脚本/提示词/模板/规则）/ 影响面 │
│   格式：跟 step11 自迭代报告完全一致，不发明新模板                  │
│   写入：docs/archive/工作流自迭代档案/YYYY-MM-DD/本轮.md          │
│   输出：方案给你审核                                             │
│                                                                  │
│ 3️⃣ 你说「确认，执行」→ 动手改                                    │
│   改完逐条回写改进建议状态 + 规则体检台账                          │
│                                                                  │
│ 4️⃣ 归档                                                         │
│   问题清单 + 方案 + 落地清单 →                                    │
│   固定路径：docs/archive/工作流自迭代档案/YYYY-MM-DD/本轮.md       │
│   同时回写：改进建议 backlog 状态列、规则体检台账                  │
└──────────────────────────────────────────────────────────────────┘
```

### 4.3 与 step11 自迭代的关系

| | step11 自迭代（每个项目结束时） | 运维流程（随时触发） |
|---|---|---|
| 触发时机 | 项目交付完成后 | 任何时候（想起来"该优化了"就说） |
| 问题来源 | 当前项目的复盘发现 | 跨项目 backlog 聚合 + 用户主动提出 |
| 流程 | 完全一致（汇总→方案→确认→执行→归档） | 同上 |
| 归档位置 | 项目 `10_交付/工作流自迭代报告.md` + 回写 `docs/archive/工作流自迭代档案/` | 直接写 `docs/archive/工作流自迭代档案/` |

**结论**：step11 是运维流程的一个特例（项目结束时自动触发），两者用同一个归档目录、同一个方案格式、同一个执行链路。
