# 工作流自迭代档案 · 归档目录约定

> 本目录存放所有**一次性**方案/诊断/设计文档的最终归档。落地后不再需要日常翻阅的文档才进这里；权威文件与活文档一律留在根目录（见 `WORKFLOW_工作流主控.md`）。

## 目录用途

- 存放工作流自迭代（step11 / 「优化」运维流程）产生的方案、诊断、设计等一次性产出物
- 归档后这些文件只作历史追溯用，不再被日常执行流程读取
- 根目录只保留指针文件、权威文件、backlog 与台账等活文档（当前 14 个 md）

## 命名规则

```
YYYY-MM-DD/方案类型_核心主题.md
```

- 目录名 = 方案产生的日期（`YYYY-MM-DD`）
- 文件名去掉 `WORKFLOW_` 前缀和日期后缀（日期由目录承载），保留「方案类型_核心主题」结构
- 跨项目的历史候选方案统一放 `历史候选方案/`

## 归档触发

- **step11 自迭代**：项目结束时自动触发，方案落地即归档
- **「优化」运维流程**：用户说「优化」后走四阶段流程（汇总问题 → 出方案 → 确认执行 → 归档），方案落地即归档
- 归档固定路径：`docs/archive/工作流自迭代档案/YYYY-MM-DD/本轮.md`（按当日日期建目录）

## 回写约定

每次归档后，**活文档里的引用路径必须同步更新**（如 `WORKFLOW_改进建议.md` 中指向方案的链接），避免留下悬空引用。归档完成需 Grep 全仓库验证无旧路径残留。

## 四阶段运维流程（与 step11 同链路）

1. **汇总问题**：改进建议 backlog 未归档条目 + 规则体检台账连续未触发规则 + 用户痛点
2. **出方案**：每条问题给出改什么/改法/落点/影响面，写入 `YYYY-MM-DD/本轮.md`，交用户审核
3. **确认执行**：用户说「确认，执行」后动手改，逐条回写改进建议状态 + 规则体检台账
4. **归档**：问题清单 + 方案 + 落地清单归档到 `YYYY-MM-DD/`，同步回写 backlog 与台账

step11 自迭代是本流程的特例（项目结束时自动触发），两者共用本目录、同一方案格式、同一执行链路。
