## 一、问题复原（先把事实钉住，不靠回忆）

| 事实 | 证据 |
|---|---|
| 机器侧全绿 | tsc 0 / build:h5 0（1164 modules）/ build:weapp 0（196 modules）/ 子应用 build 0 / 契约 0 越界 / secrets 0 硬编码 / `docker compose config` exit 0 |
| 方向稿流程走了、也拍板了 | G9 出 A/B/C 三张稿，2026-11-13 用户拍板「方向 A 工程文档式克制，主蓝 #2563FF + 辅绿 #0E9F8A」 |

**一句话根因**：现有流程保证「有没有发散」，不保证「发散源本身不同质」；视觉放行判据仍握在 Agent 手里。

## 二、五条改法（每条写清 落点 / 验收口径 / 回滚）

### 改法 1 · step02 前端设计方向强制「外部参照物」

- **落点**：`prompts/step02_技术架构设计.md`「§ 前端设计方向」小节
- **改法**：方向稿必须附 **≥2 张真实竞品 / 设计系统截图**（可搜图取得，写明来源 URL），并逐张写「参考它的什么」+「我们偏离什么」。禁止只写形容词。缺截图或只写形容词 → 方向稿打回。
- **验收口径**：`02_架构设计/门面页方向稿.md` 内有「参照物清单」表（≥2 行，含图片路径/URL + 参考点 + 偏离点）；无表 = 打回。
- **成本**：每项目多 20–30 分钟。

### 改法 2 · step05B 三版发散加「结构性反例」硬约束

- **落点**：`prompts/step05B_前端开发.md` 精修模式·三版发散段
- **改法**：三版中**至少 1 版必须是结构性反例**——同时不满足以下任两项：卡片栅格布局 / 蓝紫渐变色系 / 居中大标题 / 对称三段式。三版若同一结构族（布局骨架、信息密度、色彩策略三项中两项相同）视为**未发散**，直接打回重发，不进入挑版。
- **验收口径**：三版目录里附「差异声明表」（布局骨架 / 色彩策略 / 信息密度 / 字体策略 四项逐版填写），有两行在 ≥2 项上相同 → 打回。
- **成本**：一次发散多一轮生图。

### 改法 3 · 视觉评审改「用户盲选」

- **落点**：`prompts/step05B_前端开发.md` 挑版环节 + `WORKFLOW_卡点协议.md`（新增条件触发卡点：portfolio/landing + 精修 → 盲选）
- **改法**：三版只给截图（去标题、去 Agent 说明文字、文件名用甲乙丙），用户先选，再听 Agent 解释。**Agent 自评分不再构成视觉放行依据**（仍可用于自查）。
- **验收口径**：`设计精修记录.md` 记录「用户盲选结果 + 选择理由（用户原话）」；无盲选记录 → 5B 不算完成。

### 改法 4 · 新增可执行「AI 味判据」清单（先 observe）

- **落点**：`scripts/design_quality_check.py`（扩展现有脚本，不新建文件）新增 `--ai-flavor` 子检查；`workflow/gate_states.yaml` 登记为 observe
- **判据 6 条**（命中 ≥2 条即 fail）：① 紫蓝/蓝绿渐变大面积铺底；② 圆角卡片阵列 ≥6 张同构；③ 居中大标题 + 副标题 + 两个按钮的三段式首屏；④ 通用 3D 插画/玻璃拟态；⑤ 假数据仪表盘（无真实数据源却画 KPI 卡）；⑥ 全站对称三段式（左文右图/三列图标）。
- **observe 口径**：第一个项目只记录命中项与人工判定（真问题/误报），累计 1 个项目无误报后转阻塞闸；误报 → 按判据号加白名单。
- **验收口径**：报告里贴「命中项 + 人工判定」逐条。

### 改法 5 · portfolio/landing + 精修：视觉未过不得进 5.5

- **落点**：`prompts/step05_5_代码独立review.md` 入口前置 + `WORKFLOW_步骤定义.md`「前端串行主干」第 4 条
- **改法**：当前口径是「5B 机器绿即可进 5.5」。改为：项目类型 ∈ {portfolio, landing} **且**设计模式=精修时，必须先有「用户盲选通过 + AI 味判据未 fail」两项，才允许进 5.5；其余类型不受影响（不扩大人工参与面）。
- **验收口径**：看板 5B 行备注写「盲选通过 / AI 味判据 x 条命中」；缺任一项而进 5.5 → 判违规回 5B。
- **成本**：只对门面类项目加一道确认，业务型项目零变化。
