# 第 7 步 · 全链路联调验证

- **角色**：资深测试工程师 / 资深集成工程师 / 资深全栈开发工程师
- **输入**：本地已能运行的前后端代码 + 第 6 步冒烟通过的主流程
- **输出物**（落盘 `07_联调/`）：
  - 《全链路联调检查清单》（本地走查用的清单 + 实测记录，属证据）
  - **问题全部记入项目根目录 `_问题台账.md`**（P0+P1 必修，P2 标 `deferred` 留档）——不再单独建「联调问题清单」
  - 6.1 修复：修改后的代码片段 + 修改影响分析 + 自测说明
  - 6.2 回归结果**写回台账**（`fixed` → `verified` / 打回 `open`），轮次日志记一行——不再单独产《联调回归验证报告》
- **循环**：用附录 A 操作手册；回归未通过就重复修复 → 回归，**不设轮次上限**。收敛判据看台账：每轮 open P0/P1 数必须单调下降；同一根因连续 3 次修复无效、或问题数回升 → 判定架构性问题，**回流第 3 步**。

## 7.1 联调检查清单 Prompt

```
你是资深测试工程师，基于以下核心业务链路，帮我梳理一份联调检查清单。
【核心业务链路】
{{从架构文档里挑出所有核心端到端流程，粘贴在这里}}
【输出要求】
1. 把每条核心链路拆成具体的操作步骤（每一步点什么、输入什么）
2. 每一步标注预期结果（页面应该显示什么、接口应该返回什么）
3. 标注需要重点关注的数据一致性检查点（比如：创建后数据库里有没有、列表页对不对）
这份清单是我在本地手动走查用的，越具体越好。
4. 严重等级划分：
   - P0 阻塞：核心业务链路完全中断、主流程无法走通
   - P1 严重：核心链路部分异常、关键数据不一致
   - P2 一般：非核心链路异常、交互联调瑕疵
5. 待优化建议：P2级问题统一放入这里，不列入本轮修复
6. 未覆盖场景：本次联调未覆盖的场景与边界
要求：覆盖所有核心链路，问题定位准确，可复现。
```

> 用户拿清单在本地一条条走；**发现的问题当场写进 `_问题台账.md`**（`来源阶段`=7）。

**联调问题分级标准：**
- P0 阻塞：核心业务链路完全中断、主流程走不通
- P1 严重：核心链路部分异常、关键数据不一致
- P2 一般：非核心链路异常、交互小瑕疵（留到后续优化）

## 7.3 第 6.2 步 · 联调定向回归验证 Prompt

**输入**：修复后的前后端代码 + 台账里 `状态=fixed` 的问题 + 修改影响分析

```
你是资深集成工程师，执行本轮联调问题修复的定向回归验证，结论写回 _问题台账.md。
【回归范围】
仅验证以下内容，不做范围外的全量联调：
1. 上一轮所有 P0、P1 级联调问题是否修复
2. 修改影响分析中提到的关联功能链路是否正常
【输出要求】
1. 已修复验证：逐条列 ID + 验证结果（通过/未通过），未通过的说明原因（我会把状态改回 open）
2. 引入新问题：在修改影响范围内新发现的问题，登记进台账（来源阶段=7，新 ID）
3. 范围外新问题：统一列入「下一轮待处理」，不纳入本轮结果
4. 结论：本轮回归是否通过、本轮 open P0/P1 数（写进台账轮次日志）
【强制规则】
严格按既定回归范围执行，不扩大联调范围，范围外问题不纳入本轮结果。
```

**输出物**：台账状态更新（`verified` / `open`）+ 「轮次日志」一行

> **P1 记账前置（强制）**：任何一条 **P1** 问题在台账里改 `verified` 之前，必须先运行
> `python scripts/log_failure.py <项目目录> --step 7 --category "<类别>" ... --rule R10`
> 写入 `_失败日志.md`。没记失败日志的 P1 不许标 `verified`（第 10 步复盘与门禁 `LOG_GAP_WARNING` 会比对台账 P1 数 vs 失败日志条数）。

## 第 7.5 步 · 数据重置（强制，重置后必须验证中文可回读）

> 本项目验收时出现 P1：流程列表中文乱码。根因是 `docker exec mysql` 未带 `--default-character-set=utf8mb4`。
> 命令模板写死，不得省略字符集参数：

```bash
# 备份（必须成功后才允许重置）
docker exec swa-mysql sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 <db> > /tmp/backup.sql'

# 重置
docker exec -i swa-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 <db> < db/init.sql

# 验证：中文必须原样回读，不是 ??? 或乱码
docker exec -i swa-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 -N -e \
  "SELECT name FROM workflow ORDER BY id LIMIT 3;"
```

**重置记录必须包含**：备份文件路径/大小、重置前后行数、上述 SELECT 的真实输出、Redis 额度键清理结果（`DEL tenant:quota:*` 或等价）。

## 第 7.6 步 · 无真实 key 的 AI 能力协议冒烟（强制，不得整项挂起）

当本机没有真实 LLM key 时，**不能**把 NL 生成 / Agent 能力整项标「无法验证」挂到遗留清单：

1. 把路由指向 mock provider（`LLM_ROUTE_*` = `*-mock`），跑通「生成 → Schema 校验 → 存草稿 → 回读 → 画布加载」全链路；
2. mock 返回内容必须是**合法 DSL**，用于验证协议与校验器，不用于验证语义质量；
3. 结论口径写「协议链路通过 / 语义质量未验证（无真实 key）」，并登记为 M5 未验证项，不得写成「功能不可用」；
4. 有真实 key 时再补 20 条语义人工评审。
