# 第 7 步 · 全链路联调验证

- **角色**：资深测试工程师 / 资深集成工程师 / 资深全栈开发工程师
- **输入**：本地已能运行的前后端代码 + 第 6 步冒烟通过的主流程
- **输出物**（落盘 `07_联调/`）：
  - 《全链路联调检查清单》
  - 《全链路联调问题清单》（P0+P1 必修，P2 留档）
  - 6.1 修复：修改后的代码片段 + 修改影响分析 + 自测说明
  - 6.2《联调回归验证报告》
- **循环**：用附录 A 模板；回归未通过就重复修复 → 回归，**最多 2 轮**；2 轮仍未解决判定为架构性问题，**回流第 3 步**。

---

## 7.1 联调检查清单 Prompt

```
你是资深测试工程师，基于以下核心业务链路，帮我梳理一份联调检查清单。
【核心业务链路】
{{从架构文档里挑出所有核心端到端流程，粘贴在这里}}
【输出要求】
1. 把每条核心链路拆成具体的操作步骤（每一步点什么、输入什么）
2. 每一步标注预期结果（页面应该显示什么、接口应该返回什么）
3. 标注需要重点关注的数据一致性检查点（比如：创建后数据库里有没有、列表页对不对）
这份清单是我在本地手动走查用的，越具体越好。
4. 严重等级划分：
   - P0 阻塞：核心业务链路完全中断、主流程无法走通
   - P1 严重：核心链路部分异常、关键数据不一致
   - P2 一般：非核心链路异常、交互联调瑕疵
5. 待优化建议：P2级问题统一放入这里，不列入本轮修复
6. 未覆盖场景：本次联调未覆盖的场景与边界
要求：覆盖所有核心链路，问题定位准确，可复现。
```

> 用户拿清单在本地一条条走，把发现的问题记成《全链路联调问题清单》。

**联调问题分级标准：**
- P0 阻塞：核心业务链路完全中断、主流程走不通
- P1 严重：核心链路部分异常、关键数据不一致
- P2 一般：非核心链路异常、交互小瑕疵（留到后续优化）

---

## 7.2 第 6.1 步 · 联调问题定向修复 Prompt

```
你是资深全栈开发工程师，基于现有前后端代码，修复联调问题清单列出的所有P0、P1级问题。
【严格执行规则】
1. 只修复清单内的联调问题，禁止任何额外的功能优化、代码重构、逻辑调整，禁止超范围修改
2. 修改前先输出「修改影响分析」：每个问题的修改点、涉及的文件/函数、可能影响的其他功能链路
3. 修改后的代码标注：// 修复联调问题-xxx 改动原因
4. 只输出有修改的代码片段，不输出完整全部代码
5. 修复完成后输出「自测说明」：每个问题的验证方法、自测步骤
禁止修改不在清单内的任何逻辑，禁止重构原有正常运行的代码。
```

**输出物**：修改后的代码片段 + 修改影响分析 + 自测说明

---

## 7.3 第 6.2 步 · 联调定向回归验证 Prompt

**输入**：修复后的前后端代码 + 原联调问题清单 + 修改影响分析

```
你是资深集成工程师，执行本轮联调问题修复的定向回归验证，输出《联调回归验证报告》。
【回归范围】
仅验证以下内容，不做范围外的全量联调：
1. 上一轮所有P0、P1级联调问题是否修复
2. 修改影响分析中提到的关联功能链路是否正常
【输出要求】
1. 已修复验证：每个原问题的验证结果（通过/未通过），未通过的说明原因
2. 引入新问题：在修改影响范围内新发现的问题，同样按P0/P1/P2分级
3. 范围外新问题：本次测试中范围外发现的新问题，统一列入「下一轮待处理」
4. 结论：本轮回归是否通过，是否需要再次修复
【强制规则】
严格按既定回归范围执行，不扩大联调范围，范围外问题不纳入本轮结果。
```

**输出物**：《联调回归验证报告》

- [ ] 已用修复轮次记录在 `_项目状态.md`；满 2 轮未过则回流第 3 步
