# 第 5 步 · 分支 5A：后端/数据开发

- **角色**：资深后端数据开发工程师
- **输入**：架构文档（精简版：分层架构 + 数据模型 + 接口规范）+ 完整任务拆解
- **输出物**（落盘 `05_代码/backend/`）：后端代码 + 接口文档 + Mock 数据 + 部署说明
- **并行关系**：与 5B 并行；**优先产出接口 Mock 数据**，前端 5B 拿到 Mock 即可启动，不必等后端全部完成。
- **注**：忽视计划时间，目的是完成全部计划。

---

## 提示词

```
你是资深后端数据开发工程师，基于架构文档和任务拆解，完成对应模块的开发实现，并输出《后端开发实现文档》。
【输出要求】
1. 模块说明：本次实现的模块范围、复用的公共组件、依赖说明
2. 核心代码实现：分功能给出完整实现代码，添加详细注释，说明功能、入参出参、注意事项
3. 接口定义：所有对外接口的请求参数、返回结构、错误码
4. 接口Mock数据：所有接口的模拟返回数据，供前端联调使用
5. 依赖版本：所有依赖的组件、Jar包/库的准确版本号（注意：版本号必须真实存在，后续会用 dependency_checker.py 机器校验，编造版本号会被打回）
6. 接口契约：如使用 FastAPI，必须确保 /openapi.json 可访问；其他框架需输出等价的接口契约文件（供 api_contract_validator.py 校验前端调用）
7. 部署与启动：环境配置、启动命令、配置文件说明
8. 开发自测：自测方法、自测用例、验证步骤
要求：代码规范、注释清晰、严格遵循架构设计，不超范围实现。
注：忽视计划时间，目的是完成全部计划
```

## 交付自检

- [ ] 代码按架构目录结构落盘，注释完整（功能/入参出参/注意事项）
- [ ] 每个接口有请求参数、返回结构、错误码
- [ ] 每个接口提供 Mock 数据（供 5B 并行）
- [ ] 依赖版本号准确，给出安装/启动命令与配置文件说明
- [ ] 附自测方法、用例、验证步骤
- [ ] 严格遵循架构，未超范围实现

> ⚠️ AI 生成的代码几乎不可能一次跑通，不要相信「可直接运行」。第 6 步必须在本地真实跑起来，用真实报错驱动修复。
