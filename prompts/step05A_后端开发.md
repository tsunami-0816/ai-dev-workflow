# 第 5 步 · 分支 5A：后端/数据开发

- **角色**：资深后端数据开发工程师
- **输入**：架构文档（精简版：分层架构 + 数据模型 + 接口规范）+ 完整任务拆解
- **输出物**（落盘 `05_代码/backend/`）：后端代码 + 接口文档 + Mock 数据 + 部署说明
- **并行关系**：与 5B 并行；**优先产出接口 Mock 数据**，前端 5B 拿到 Mock 即可启动，不必等后端全部完成。
- **注**：忽视计划时间，目的是完成全部计划。

---

## 效果度量

- **目标**：产出可运行的后端代码，装依赖/起服务/核心接口可访问
- **启动前 checklist（M1 环境启动域）**：
  1. 端口分配：从 `WORKFLOW_端口分配表.md` 取项目端口前缀，确认端口没被占
  2. 依赖锁定：requirements.txt / pom.xml 锁版本，有 lock 文件（requirements.txt / pom.xml）
  3. 配置文件：复制 `.env.example.template` 为 `.env`，填入实际值，配置项和代码一一对应
  4. 中间件：复制 `docker-compose.yml.template` 为 `docker-compose.yml`，改端口后 `docker compose up -d` 能起来
  5. 配置探活：`python scripts/env_preflight.py --verify-config` 全绿
- **成功标准**：
  1. `pip install` / `mvn compile` 成功
  2. 服务能启动，健康检查 URL 返回 200
  3. 每条 P0 链路至少跑通一次最小闭环
  4. OpenAPI 契约文件 paths > 0（导出前必须校验，paths=0 不覆盖已有文件）
- **失败信号**：
  1. 装依赖失败（版本冲突 / 包不存在）
  2. 起服务报 ERROR（Bean 装配失败 / 端口被占）
  3. 核心接口 404 / 500
  4. 5.5 reviewer 打回
- **度量方式**：`env_preflight.py --smoke <健康检查URL>` 全绿 + 5.5 reviewer 通过

### 5A 收尾「最小启动冒烟」（强制，缺一不得宣布 5A 完成）

> 编译通过 ≠ 能跑。本项目 4 条失败都是「`mvn compile`/`npm build` 过了但启动报错、Bean 装配失败、路由 404」。

- [ ] 服务真实启动成功，日志无 ERROR/Exception 栈
- [ ] 用真实账号调通登录接口，拿到 token
- [ ] 调通 1 个**带路径参数**的接口（不是只有 `/health`），确认路由与参数绑定正确
- [ ] 调通 1 次核心业务流程（哪怕是最小执行），确认 DB 读写与事务正常
- [ ] 以上 4 条的命令、返回码、关键响应片段贴进《后端开发实现文档》「自测」章节

> ⚠️ AI 生成的代码几乎不可能一次跑通，不要相信「可直接运行」。第 6 步必须在本地真实跑起来，用真实报错驱动修复。
> 依赖校验：`python scripts/dependency_checker.py <项目根目录> --solve`（单包存在 ≠ 整体可解）。

### 幂等规范（G10）

- 长耗时脚本 / 批量任务**先查后写**：按唯一业务键判断是否已存在，不依赖上次运行的残留状态
- 重复执行不造出重复数据（重复提交、重复消息、重复记录）；需要重置时走 step7.5 数据重置口径
- 外部调用具备重试与兜底，失败不留半完成状态

### Mock 使用红线（违反即视为未完成）

1. 所有 Mock 返回必须在代码里带 `# MOCK:` 注释，写清「替代什么真实依赖、上线前怎么替换」；
2. 同时在 `_设计实施映射表.md` 对应行备注 `Mock: <依赖>`，并登记到看板遗留清单（P2 或 deferred），不得悄悄留在代码里；
3. **Mock 只能替代外部依赖**（第三方 LLM/短信/支付/硬件），不得用 Mock 冒充本项目自己的核心业务逻辑；用 Mock 把「功能没写」包装成「功能可用」= 第 10.0 门禁直接打回。
