# 第 2 步 · 技术架构设计

- **角色**：资深软件架构师
- **输入**：第 1 步《项目基线说明书》（**全量**粘贴）
- **输出物**：《第一轮技术架构设计文档》→ 落盘 `02_架构设计/第一轮技术架构设计文档.md`

---

## 提示词

```
你是资深软件架构师，基于《项目基线说明书》，输出完整的《第一轮技术架构设计文档》。
【输出要求】
1. 技术选型说明：对应基线需求的组件选型、版本选择理由、兼容性说明
2. 整体分层架构：按接入层、存储层、计算层、服务层、应用层、运维层划分，明确每层职责与组件
3. 核心业务链路：梳理所有核心业务流程，画出端到端的数据流/调用链，明确每个节点的输入、处理逻辑、输出
   - **末尾必须单列一节「§ 设计要素与端到端链路清单」**：把本文档里所有要落地的功能点、页面、接口、组件、链路节点逐条编号列出（`D-01` 递增），一条一行，写清「设计项 → 所属链路 → 预期用户可见结果」。
   - 这一节是第 4 步 `_设计实施映射表.md` 的抄录来源：清单里有的，映射表必须有一行；清单里没有的设计项不许出现在映射表里当挡箭牌。
4. 数据模型设计：核心表结构设计、字段规范、主键/分区/索引设计、表关联关系
5. 接口规范定义：统一的API请求/返回格式、错误码规范、鉴权规则，核心接口清单
6. 部署架构设计：部署方式、高可用方案、弹性扩缩容策略、环境划分
7. 监控与运维：监控指标体系、告警规则、运维流程
8. 技术风险与应对方案：核心风险点、兼容性风险、性能风险、应对方案
9. **新依赖可解性（G4）**：选型引入的每个第三方包，必须过 `python scripts/dependency_checker.py <项目目录> --solve`，"包查得到但装不上"（版本冲突 / 传递依赖缺失）在选型阶段拦下，不带进开发。
10. **外部 API Key 取用（G11）**：识别到需要外部 API（LLM / embedding / 短信 / 支付等）时，直接从全局仓库 `D:\lg\project\resources\api-keys.env` 复制对应配置到项目 `.env`；项目目录内不复存 key 原件，`.env` 走 `.secretignore` / `.gitignore`，`prepush_check.py` git 历史密钥扫描兜底。新增 key 时在全局仓库文件登记用途、来源、新增日期；发现泄露立即去对应控制台吊销。
11. **门面页方向稿（G9，仅 landing / portfolio 或看板标注含门面页时；纯后端、b2b-admin 不触发）**：step2 定稿后、5B 动工前，产出 `02_架构设计/门面页方向稿.md` + 1~2 张方向稿（静态图或可玩原型）+ 一句话设计意图。要素沿用 #85 废词黑名单口径：HEX 色值、字体与字重、圆角 px、间距密度、布局特征、**明确不做什么**；禁止「现代 / 简洁 / 科技感 / 高级」类废词。方向稿定气质与布局比例，不逐像素锁死。**👤 用户确认方向后 5B 才按稿实现；未确认不动工。** 现有 R24「功能后三版发散 + 空上下文视觉评审」保留为实现后精修兜底。

【精修模式专属（仅当看板「设计模式=精修」时输出）】
9. 设计方向定义（R24）：
   **开工前必读**：
   - `skills/active/distinctive-ai-design/SKILL.md`：按「探索→定义→交付」流程，先给 3 个真正不同的视觉概念（差异在构图/信息组织/字体/交互，不能只换颜色），再收敛成 brief
   - `skills/active/qiaomu-design/SKILL.md`：按中文设计顾问方法论做诊断和方向选择
   - 项目类型 = landing/portfolio 时，加读 `skills/motion/motion-web/SKILL.md`
   - 没思路时可跑 `npx ui-ux-pro-max-cli suggest --scene <b2b-admin|landing|portfolio>` 查风格参考（可选）

   包含：
   - 整体风格定位：2-3 个候选方向（如「简洁现代 B 端后台」「深色科技感」「清新数据可视化」），说明各自的气质、适用场景、优缺点
   - 主色调方案：从候选方向里选定一个，给出主色 / 辅助色 / 背景色 / 文字色的具体色值（hex）
   - 字体与排版方向：字体选择思路（系统默认 / 定制字体）、标题与正文的层级关系
   - 布局与间距规范：页面整体布局思路、卡片间距、页面边距的大致量级
   - 明确「不做什么」：避免哪些 AI 模板感设计（如紫蓝渐变、过度发光、卡片套卡片、三卡片等宽网格、玻璃拟态滥用——对照 `skills/active/design-skill-master/SKILL.md` 的 10 个 tell）
   - 末尾标注：用户最终选定的方向（待用户确认后回填）
要求：设计完整、边界清晰、可直接指导开发，优先考虑可扩展性与可维护性。
```

## 交付自检

- [ ] 八项输出要求齐全，组件/版本号具体、可落地
- [ ] 六个分层均有职责与组件说明
- [ ] 每条核心业务链路都有端到端输入/处理/输出
- [ ] 末尾有「设计要素与端到端链路清单」，全部条目带 D-编号，且每条标明所属链路与用户可见结果
- [ ] 表结构、接口规范可直接指导第 5 步开发
- [ ] 技术风险与应对一一对应，不写空话
- [ ] 新引入第三方包过了 `dependency_checker.py --solve`，无可解性冲突
- [ ] 需要外部 API 时，配置取自全局 key 仓库，项目内未复存 key 原件
- [ ] 触发 G9 的项目：`门面页方向稿.md` 已落盘，要素具体（色值/字重/圆角/间距/布局/不做什么），无废词，待用户确认后再交 5B
