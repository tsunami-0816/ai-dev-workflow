# 第 2 步 · 技术架构设计

- **角色**：资深软件架构师
- **输入**：第 1 步《项目基线说明书》（**全量**粘贴）
- **输出物**：《第一轮技术架构设计文档》→ 落盘 `02_架构设计/第一轮技术架构设计文档.md`

---

## 提示词

```
你是资深软件架构师，基于《项目基线说明书》，输出完整的《第一轮技术架构设计文档》。
【输出要求】
1. 技术选型说明：对应基线需求的组件选型、版本选择理由、兼容性说明
2. 整体分层架构：按接入层、存储层、计算层、服务层、应用层、运维层划分，明确每层职责与组件
3. 核心业务链路：梳理所有核心业务流程，画出端到端的数据流/调用链，明确每个节点的输入、处理逻辑、输出
4. 数据模型设计：核心表结构设计、字段规范、主键/分区/索引设计、表关联关系
5. 接口规范定义：统一的API请求/返回格式、错误码规范、鉴权规则，核心接口清单
6. 部署架构设计：部署方式、高可用方案、弹性扩缩容策略、环境划分
7. 监控与运维：监控指标体系、告警规则、运维流程
8. 技术风险与应对方案：核心风险点、兼容性风险、性能风险、应对方案
要求：设计完整、边界清晰、可直接指导开发，优先考虑可扩展性与可维护性。
```

---

## 交付自检

- [ ] 八项输出要求齐全，组件/版本号具体、可落地
- [ ] 六个分层均有职责与组件说明
- [ ] 每条核心业务链路都有端到端输入/处理/输出
- [ ] 表结构、接口规范可直接指导第 5 步开发
- [ ] 技术风险与应对一一对应，不写空话
