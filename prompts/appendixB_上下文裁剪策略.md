# 附录 B · 上下文裁剪策略（防止越喂越长）

> 每一步不要把上一步的全部输出都粘回去。Agent 在执行「单步执行协议」第 2 步时，必须按下表决定带入哪些内容；历史决策沉淀在项目文档与 `_项目状态.md` 中，不每次回灌。

| 流转 | 应带入的内容 |
|---|---|
| 第 1 步 → 第 2 步 | 完整《项目基线说明书》（**必须全量**） |
| 第 2 步 → 第 3 步 | 完整架构文档（**必须全量**，评审需要看全貌） |
| 第 3 步 → 第 4 步 | 只带评审通过的**最终版架构文档** + 评审报告中的「已确认结论」 |
| 第 4 步 → 第 5 步 | 架构文档**精简版**（只留分层架构 + 数据模型 + 接口规范）+ 完整任务拆解 |
| 第 5 步 → 第 6 步 | 只贴报错相关文件，**不贴全部代码** |
| 第 6 步之后的修复循环 | 每次只贴「问题清单 + 上次改过的文件」，不贴历史全部内容 |
| 第 9 步 → 第 10 步 | 让 AI 读取项目文件夹里的所有文档（若用 Cursor/Trae 等带代码库索引的工具，直接让它自己读，不要手动粘贴） |

**原则**：越往后走，越只贴「当前正在改的那部分」；把历史决策沉淀在文档里，不要每次都喂回去。

## Agent 落地要点

1. 产物已落盘的，优先用「读文件」按需取片段，而不是在对话里重复全文。
2. 跨对话恢复时，先读 `_项目状态.md`，再按上表读取本步所需的最小输入。
3. 标注「必须全量」的两个流转（1→2、2→3）不得裁剪，否则评审与设计会失真。
4. 修复类循环严格限定「问题清单 + 上次改动文件」，避免上下文膨胀导致漏改、误改。
