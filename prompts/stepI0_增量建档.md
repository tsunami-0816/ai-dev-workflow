# I0 · 增量建档（迭代线第一步）

- **角色**：项目分析师 + 架构师
- **输入**：已闭环项目（v1 产物齐全：`01_项目基线说明书.md`、`_设计实施映射表.md`、`08_测试/基线指标验证表.md`、`_失败日志.md`、`_问题台账.md`）+ 用户给的增量目标
- **输出物**：`01_项目基线说明书.md` 内的**增量段**（不新建基线文件）+ 看板补「迭代轮次」「上一轮 commit」
- **作用**：在既有 v1 项目上把「这次加什么、动哪里、哪些不能退、怎么回滚」定成可核对的增量基线，再交 I1 设计评审。

---

## 开工前置（先核对，不满足不开工）

1. **目标项目必须已闭环**：10.0 门禁全绿、step9 验收通过、8.5 P0/P1 清零。未闭环项目不走迭代线，回生产线/翻新线补齐。
2. **读 v1 实测产物**（数字唯一来源，禁止拿 v1 设计书目标值冒充实测）：
   - `01_项目基线说明书.md`（v1 指标与范围）
   - `_设计实施映射表.md`（v1 已实现/砍掉/未验证条目）
   - `08_测试/基线指标验证表.md`（v1 实测值）
   - `_失败日志.md`、`_问题台账.md`（v1 已知坑与 deferred 项）
3. 看板「路线」填 `迭代`；记「迭代轮次」（v2、v3…，上一轮是 v1 就填 v2）与「上一轮 commit」（增量开工前 HEAD commit hash，`git rev-parse HEAD` 取）。

## 增量段必含五块（写进 `01_项目基线说明书.md` 末尾「## 增量段（<轮次>）」小节）

### 1. 增量范围

- 本轮要加的能力：逐条写清「解决谁的什么问题、对应哪个 JD 缺口或简历增量」。
- 明确**不做什么**：本轮排除的增量项及砍掉依据（硬件/复杂度/非核心）。

### 2. 影响面（改动 / 复用 / 新增 / 废弃，逐项列清）

| 类别 | 对象（文件/模块/接口/表） | 说明 | 是否触及既有契约/数据模型/对外行为 |
|---|---|---|---|
| 改动 | | 在 v1 既有代码/文档上改了什么 | 是 / 否 |
| 复用 | | 直接沿用的 v1 模块/接口/表 | — |
| 新增 | | 本轮新写的模块/接口/表 | — |
| 废弃 | | 本轮下线/替换的 v1 项（无则写「无」） | 是 / 否 |

> 影响面未列清不进 I1。触及既有契约 / 数据模型 / 对外行为的项，在「是否触及」列标「是」，I1 评审时进 R-3 高风险确认清单。

### 3. 指标归属（沿用 / 演进 / 新增 三分类）

指标表固定列：`指标ID | 归属版本 | 类型 | 指标描述 | v1 基线值 | 本轮目标值 | 实测值 | 口径/来源`

- **沿用**：v1 已有、本轮不动的指标。v1 基线值从 v1 实测产物回填，本轮目标值=不低于 v1。
- **演进**：v1 已有、本轮要改/优化的指标。v1 基线值回填，本轮目标值写清方向（如 P95 从 X 降到 Y）。
- **新增**：本轮才有的指标。v1 基线值写「—」，只看本轮达标。
- 「实测值」列 I0 阶段留空，由 I2 第 8 步回填；v1 基线值禁止填设计书目标值，必须来自 v1 实测产物。

### 4. 不退化基线

- 从 v1 实测产物摘出本轮必须守住的既有行为与指标：核心主流程、沿用类指标、已交付承诺（接口契约/对外行为/文档口径）。
- 每条写清「守住判据」（可机器核对或可人工走查），供 `scripts/incremental_regression_check.py` 与 I2 验收对照。

### 5. 回滚预案

- 本轮增量段如何单独回滚：回滚到「上一轮 commit」的方式（git revert/分支/配置开关）、回滚影响面、回滚后 v1 产物应保持什么状态。
- 增量改动与 v1 历史不揉成一团：本轮新增/改动可单独识别、单独撤销。

---

## 硬规则

1. **不新建项目目录、不复制整套模板骨架**：增量在既有 `projects/<项目名>/` 上叠加；v1 原始产物只读不改（除在基线说明书内追加增量段这一处）。
2. **数字只取 v1 实测产物**：v1 基线值指不回去实测文件的，标「未验证」，不许估、不许抄目标值。
3. **影响面逐项落文件/模块**：禁止「改了相关模块」这类空话；每条改动/复用/新增/废弃必须指到具体文件、接口或表。
4. **不退化基线必须可核对**：写不出守住判据的指标，不进不退化清单，转 deferred 并在诚实边界说明。
5. 增量段写完即交 I1；本步不写实现代码、不改 v1 代码。
