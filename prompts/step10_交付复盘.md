# 第 10 步 · 上线交付与复盘

- **角色**：资深项目经理
- **输入**：所有文档 + 验收通过的系统
- **输出物**（落盘 `10_交付/`）：项目交付包 + 上线方案 + 复盘报告

---

## 提示词

```
你是资深项目经理，基于以上所有文档与最终验收通过的系统，输出《项目交付包与复盘报告》。
【输出要求】
1. 交付清单：完整的代码目录结构、配置文件清单、依赖版本清单、接口文档、部署文档、运维手册
2. 上线方案：部署步骤、环境变量清单、数据库初始化脚本、回滚方案
3. 项目复盘：
   - 项目整体完成情况，指标达成情况
   - 过程中遇到的核心问题与根本原因
   - 【强制】失败归因分析：读取项目根目录 `_失败日志.md`，统计：① 返工最多的步骤 Top3；② AI 犯错最多的类型（按根因分类聚类）；③ 人工卡点拦截了多少 AI 未发现的问题；④ 哪些失败本可通过机器校验提前拦截。用数据说话，禁止凭印象写「过程中遇到了一些困难」
   - 可复用的资产、组件、Prompt 模板
   - 流程改进建议（必须基于失败日志数据提出，每条建议对应至少一条真实失败记录）
4. 后续迭代规划：遗留问题（P2/P3）清单、下版本功能方向
```

---

## 交付自检

- [ ] 交付清单可照单清点：代码目录、配置、依赖版本、接口/部署/运维文档齐全
- [ ] 上线方案含部署步骤、环境变量、数据库初始化脚本、回滚方案
- [ ] 复盘对照基线逐条说明指标达成情况与核心问题根因
- [ ] 沉淀可复用资产（组件、Prompt 模板）与流程改进建议
- [ ] 汇总第 7/8 步遗留的 P2/P3 问题，给出下版本方向
- [ ] 在 `_项目状态.md` 将项目标记为「已交付」
