# 第 10 步 · 上线交付与复盘

- **角色**：资深项目经理
- **输入**：所有文档 + 验收通过的系统 + 项目根目录 `_失败日志.md` / `_问题台账.md` / `_设计实施映射表.md`
- **输出物**（落盘 `10_交付/`，**两份文件，文件名写死，不许合并、不许改名**）：
  - **`10_交付/交付复盘.md`**：项目复盘 + 失败归因 + 选题准确率复盘 + **项目结果卡（5 个数）** + 后续迭代规划
  - **`10_交付/交付包与上线方案.md`**：交付包清单 + 上线方案 + **10.7 环境收尾留证**
- **门禁**：两份文件都落盘后跑 `python scripts/workflow_completion_check.py <项目目录>`（10.0 门禁），全绿才能进 10.5

## 10.5 GitHub 推送前 .gitignore 必查（强制）

> 实测 nestjs-agent-workbench 项目根目录和 frontend/ 缺 .gitignore，差点把 node_modules/.env 推上去。

push 到 GitHub 前必须确认三处 .gitignore 存在且包含 `node_modules/`、`.env`、`dist/`、`__pycache__/`、`.pytest_cache/`：
- 项目根目录 `.gitignore`
- `backend/`（或后端代码目录）`.gitignore`
- `frontend/`（或前端代码目录）`.gitignore`

跑一遍 `git status` 确认 `.env`、`node_modules/` 不在 untracked 列表里。`.env.example`（占位符模板）可以提交，真实 `.env` 必须不提交。

## 10.7 环境收尾（强制，交付的最后一步）

> 开发/测试期起的服务不关，会一直占内存与端口，污染下一个项目的环境预检与端口分配。
> 实测：本项目验收后仍有 3 个应用进程 + 3 个容器在跑，占着 8083 / 5177 / 8085 / 3310。

1. **先关应用进程**：按 `WORKFLOW_端口分配表.md` 里本项目占用的端口查占用，**确认命令行归属后**再停止，禁止按进程名盲杀（同机可能有别的项目同名进程）。
   ```powershell
   Get-NetTCPConnection -LocalPort <本项目端口列表> -State Listen |
     ForEach-Object { Get-CimInstance Win32_Process -Filter "ProcessId=$($_.OwningProcess)" |
       Select-Object ProcessId,Name,CommandLine }
   Stop-Process -Id <确认过的 PID> -Force
   ```
2. **再关本项目容器**：`docker compose -f 05_代码/docker-compose.yml down`；单独 `docker run` 起的容器（如 `swa-mysql`）用 `docker stop <name>`。**不删数据卷**；镜像的去留见第 6 条空间回收。
3. **不动共享中间件**：端口分配表标注「本机共享」的 MySQL / Redis 等保持运行；确需停止时先确认没有其他项目在用，并在记录里写明理由。
4. **留证**：把端口复查输出贴进 `10_交付/交付包与上线方案.md` 的「环境收尾」小节，写明停止的进程 PID/端口、停止的容器名、保留的共享服务、复查结果（哪些端口已释放、哪些仍被其他项目占用）。
5. **前置条件**：DB 备份与初始化脚本必须在关闭前已产出，关闭服务不得导致交付包缺件。
6. **空间回收（项目完结时执行，防磁盘被历史项目吃满）**：
   - **构建产物/依赖目录可删**（随时能重装回来）：`node_modules/`、`.venv/`、`__pycache__/`、`target/`、`dist/`、`build/`、`.pytest_cache/`、Allure 结果目录。删除前确认 `requirements.txt`/`package.json`/lock 文件在，能一键重装。
   - **项目自建 docker 镜像可删**（`docker images` 里按项目名/compose 项目前缀过滤）；**共享基础镜像不删**（mysql/redis/kafka 等官方镜像别的项目还要用）；**数据卷不删**。
   - **不删的**：源码、文档产物、`_失败日志.md`/`_问题台账.md`、Git 历史、数据库数据卷。
   - 把删了什么、释放了多少空间（删前删后 `docker system df` / 目录大小）写进 `10_交付/交付包与上线方案.md` 的「环境收尾」小节。
