## 铁律（先看这条，违反就重写）

0. **去 AI 味**：开工前 Read `skills/content/humanizer-zh/SKILL.md`，按它的规则删中文里的空话、重复、模板化表达。简历不是小红书，但"深入理解""高效""赋能"这种词一样要砍。

1. **设计书里的目标值不是实测值。** 第 1 步写的「30 秒响应」「85% 准确率」「支持 XX 并发」是**目标**，实际做出来常常不一样（真实案例：基线写 30 秒，实测 61 秒；基线写 500 QPS，压测只有 180）。
   → 简历里的**每个数字必须来自实测产物**，并在「数据出处映射表」里写出文件与位置。
2. **没有实测 = 写「未验证」，不许估、不许抄目标值、不许四舍五入美化。**
3. **做过什么就写什么。** Mock 必须写 Mock，骨架必须写骨架；`_问题台账.md` 里 `deferred` 的项要如实进「诚实边界」。
4. **禁用无法证伪的形容词**：精通、熟练掌握、深入理解、主导、负责整个项目、架构师级。改成可验证的动作 + 结果。
5. **STAR 是骨架，不是八股。** 每段都要有具体对象（哪个接口、哪个表、哪个模块），不写「提升了系统性能」这种空话。

## 10.6.1 产出 A · 简历项目描述

**结构（全部必填，总长 300 字以内，另附可粘贴纯文本块）**

| 段 | 要求 |
|---|---|
| A 一句话 | ≤40 字：业务场景 + 技术栈核心 + 规模（表数/接口数/模块数，取实测） |
| S 背景 | 2-3 句：解决谁的什么问题，约束是什么（必须带上本机硬件约束这条真实限制） |
| T 目标 | 2-3 条可判定目标，与第 1 步基线对应，但**只写最终达成/未达成的实测值** |
| A 动作 | 4-6 条，每条格式「做了什么 → 为什么这么选 → 落到哪个模块」。优先写有技术含量的：多租户隔离、JWT、事务幂等、流式输出、限流、契约校验 |
| R 结果 | **全部实测**：接口数、表数、用例通过率、压测 TPS/P95、P0/P1 归零、核心流程耗时；未验证指标单独列一行「未验证」 |
| C 关键词 | 按 `00_JD对账表.md` 逐项列，标注「用过 / 了解 / 未用」三档，不许全都标「用过」 |
| D 可演示点 | 3 条，每条必须是第 9 步验收清单里真实通过的条目 |
| E 诚实边界 | 一段话：哪些是 Mock/骨架、哪些 deferred、哪个指标没验证。**这段不能省**——面试官一问就穿帮的地方，主动写出来反而是加分项 |

**格式要求**：正文 300 字内；末尾给一段可直接复制进简历的纯文本（不带 markdown 星号/emoji）；不要「项目描述：」这类前缀。

## 10.6.5 反向回写求职侧（必须执行，不许跳过）

> 这一步是工作流 → 求职流水线的反向通道。只产出简历文档不回写，等于项目做完了但求职侧还在原地等。

产出 A/B 两份文件后，**必须依次做以下三件事**：

### ① 回写等项目的 JD

扫 `D:\lg\resume\JD仓库\` 下所有 `.md` 文件，找到状态行包含 `⏳等项目` 的 JD：

- 打开该 JD，看「⏳ 暂缓投递档案」区块的「待补项目」清单
- 如果清单里有刚做完的项目名，把对应的 `- [ ]` 改成 `- [x]`，后面补上完成日期和 GitHub 链接
- 把 JD 顶部的状态行从 `⏳等项目（xxx 补 yyy 缺口）` 改成 `✅项目已补（项目名 已于 YYYY-MM-DD 完成，可出简历）`
- 如果待补清单全部勾完，在 JD 末尾追加一行：`> 🔥 全部缺口已补，可推进出简历。`

### ② 加进弹药库索引

打开 `D:\lg\resume\素材与脚本\PROJECT_INDEX.md`：

- 在「二、备选项目」表格末尾加一行（新项目先放备选，投了有面试反馈再升核心）
- 列：项目名、方向标签、一句话卖点、本地路径、简历素材路径
- 同步更新「四、方向→项目速查」表，如果新项目补了某个方向的缺口
- 更新文件顶部「最后更新」日期

### ③ 告知用户

做完①②后，在最终回复里明确告诉用户：

> 🔄 反向同步完成：
> - 更新了 JD：<公司名> <岗位名>（状态：⏳等项目 → ✅项目已补）
> - 加进弹药库：<项目名>（备选 #编号）
> - 下一步：要现在重出 <公司名> 的 PDF 简历吗？

如果扫完没有任何 JD 处于「⏳等项目」状态，跳过①，但②③仍要执行。
