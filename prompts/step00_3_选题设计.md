# step 0.4 · 候选选题矩阵

> 模板文件名 `step00_3_选题设计.md` 是设计模块 3 份提示词模板中的第 3 份（`step00_1` / `step00_2` / `step00_3`）；它服务WORKFLOW_步骤定义.md 的 **0.4 候选选题矩阵** 步骤，WORKFLOW_步骤定义.md「提示词模板」列按此文件名引用。

- **角色**：资深技术面试官 + 全栈架构师
- **输入**：`00_JD技能点清单.md`（0.1）+ `00_作品集画像库.json/.md`（0.2）+ 缺口分析结论（0.3，无独立文件时按 0.1/0.2 直接分析）+ 硬件约束 + `docs/个人项目不可实现清单.md`
- **输出物**：`00_选题矩阵.md` → 落盘本轮 step00 设计工作目录
- **模块位置**：设计模块第 4 步（WORKFLOW_步骤定义.md 0.4；设计说明见 `docs/step00_JD选题模块设计.md` §1.4、§2 反粗制滥造 6 道闸、§3 硬件约束）
- **卡点**：👤 **卡点 1 方向拍板**——选题矩阵落盘后必须停下，输出候选清单等用户选哪几个、砍哪几个、业务场景是否认可；用户拍板后才进 0.5，不替用户下结论

## 提示词（直接套用，代码块内为可粘贴全文）

```
你是资深技术面试官 + 全栈架构师。基于 JD 技能点清单、已有项目画像库和缺口结论，设计候选项目选题矩阵。

【目标】
用最少的项目覆盖 JD 高频技能点缺口、能讲出技术深度、工作量可控、不与现有作品集撞车。你的产出是「候选清单」不是最终决定——用户会在卡点 1 拍板选哪几个。

【输入】
{{skills_table}}            ← 00_JD技能点清单.md（含每份 JD 的 must_have / nice_to_have / red_flags）
{{portfolio_json}}          ← 00_作品集画像库.json（已有项目覆盖了哪些技能点、深度如何）
{{gap_analysis}}            ← 0.3 缺口分析（无独立文件时你自己按 0.1 ∩ 0.2 做差集并写明口径）
硬件约束（写死，违反直接打回）：RTX 2050 4GB 显存 + 16GB 内存；禁止本地 7B+ 模型微调/推理、禁止 K8s 集群/多节点部署、禁止 GPU 训练的 CV/多模态项目、禁止超过 5 个服务的微服务拆分（详见 docs/step00_JD选题模块设计.md §3）。
砍词字典：docs/个人项目不可实现清单.md（JD 里的这些词要主动砍，不硬塞）。

【数量与结构】
候选项目 2-3 个，最多 5 个。每个项目必须写全下面 10 项，缺一项整条打回：
1. 一句话定位（解决谁的什么小问题）
2. 业务场景（3-5 行，小而真；禁止「XX 电商平台」「XX 管理系统」这种大而空）
3. 技术栈组合（具体到组件与版本级别，且必须能在本机装起来）
4. MVP 最小可用场景（R18）：做完之后用户能实际完成的一件有意义的事，一句话，例如「拖 3 个节点连线 → 配 HTTP URL → 点执行 → 看到每步真实输出」
5. 硬骨头模块 1-2 个：每个写清「问题是什么 / 我的方案是什么 / trade-off 是什么 / 为什么面试能讲 10 分钟」；写不出硬骨头的项目直接毙掉（反 CRUD 换皮）
6. 工作量预估：**预估步骤轮次 × 模块 + 卡点次数 + AI 协作系数**，禁止写人天（AI 全程协作下人天口径已失真）；超出单项目承受范围的强制砍到 MVP，高级特性列「可选加分项」
7. 与已有项目的差异化说明：技术栈组合 + 业务领域两个维度不能同时撞车（撞车=双维度都重复）；给出去重依据
8. 项目类型建议（供 step01 确认，影响后续 skills 加载）：b2b-admin / internal-tool / landing / portfolio
9. JD 技能点覆盖：列出覆盖哪些缺口技能点；must_have 覆盖率必须 100%，实在覆盖不了的写「本项目不覆盖，由项目 N 覆盖」（不允许不写）
10. 主动砍掉的 JD 词 + 砍掉理由（硬件/复杂度/JD 权重/非核心）

【反粗制滥造 6 道闸（全部自检过才能交）】
1. JD 高频技能点覆盖率 <100% → 补设计或写明由哪个项目承担；
2. 与已有项目「技术栈 + 业务领域」双撞车 → 改或毙掉；
3. 每个项目至少 1-2 个硬骨头模块（能讲「自己实现了 XX 机制」/「解决了 XX 一致性/性能问题」）；
4. 面试三问必须答得出：为什么用 A 不用 B / 最难的问题 / 再做一次怎么改；
5. 工作量预算超单项目承受范围 → 砍到 MVP；
6. 候选项目两两对比，技术栈/业务领域/硬骨头三个维度不能有两个雷同。

【求职方向约束（选型时就要体现）】
用户求职方向是 **Java 后端 + 测试开发双栖**：技术选型优先 Java 生态（Spring Boot / Spring Cloud、MyBatis、MySQL、Redis、Kafka 等）；测试体系必须真正做扎实（自动化分层、性能压测、安全扫描都要能落进项目），不要做成只有业务 CRUD 的演示项目。

【落盘（必须执行）】
写成 `00_选题矩阵.md`（文件名必须逐字一致），结构固定：
# 00_选题矩阵
## 一、缺口结论
（must_have 缺口 / 浅层覆盖需做深的 / 主动砍掉的词；写清口径：0.1 ∩ 0.2 差集）
## 二、候选项目总表
| 项目名 | 一句话定位 | 业务场景 | 技术栈组合 | 覆盖 must_have 数 | 硬骨头数 | 步骤轮次预估 | 项目类型建议 | 与已有项目差异化 |
## 三、候选项目详案
### 候选 1：<项目名>
（按上面 10 项逐条写）
### 候选 N：…
## 四、技能点覆盖对账
| JD 技能点（must_have 优先） | 由哪个候选项目覆盖 | 依据（模块/机制） | 未覆盖时由谁承担 |
## 五、待用户拍板事项（卡点 1）
- 选哪几个、砍哪几个、优先级排序；
- 业务场景是否认可 / 要不要换；
- 有没有候选项目需要合并。
写完后停止，等用户拍板。**不要**在这一步直接产出 00_项目设计书.md 或复制项目骨架。

【自检后再说完成】
- 候选 2-3 个（最多 5），每个 10 项齐全；
- must_have 覆盖率 100% 或写明承担项目；
- 任意两个候选在技术栈/业务领域/硬骨头三维度没有两项雷同；
- 没有写「人天」，全部用步骤轮次 + 卡点次数 + AI 协作系数；
- 没有「XX 电商平台 / XX 管理系统」类空泛场景；
- 没有违反硬件约束的选型；
- 面试三问真的答得出（不是占位）。
```

## 卡点 1 之后（用户拍板后怎么走）

1. **0.5 一页纸项目设计书**（WORKFLOW_步骤定义.md 0.5，无提示词模板）：按 `docs/step00_JD选题模块设计.md` §1.5 的 9 节结构写每个选中项目，落盘 `00_项目设计书.md`；JD 覆盖对账落盘 `00_JD对账表.md`，表头必须含 `step10 落地验证` 列（值为「真实落地 / 降级 / 纸面」，step10 复盘回填）。
2. **过 WORKFLOW_卡点协议.md「机器闸门」**（2026-10-30 R20 起由人工确认降级为机器闸门）：跑 `scripts/dependency_checker.py`（依赖真实性）+ `scripts/env_preflight.py`（本机工具/端口/内存）+ `scripts/skills_coverage_checker.py`（技能点覆盖率 100% + 设计书必备节），并确认工作量拆解不超单项目承受范围、设计书含「MVP 最小可用场景」一句话（R18）。**全绿直接进 step01，不等用户确认；报红才把报红项 + 建议改法列给用户拍板。**
3. 只入预备仓库：建 `projects/_队列/<项目名>/`，放入 `00_项目设计书.md` + `00_JD对账表.md`，队列追加一行状态「待开工」。不复制骨架、不建空项目目录。

## 交付自检

- [ ] 候选项目 2-3 个（最多 5 个），每个 10 项齐全（定位/场景/技术栈/MVP/硬骨头/工作量/差异化/项目类型/覆盖/砍词）
- [ ] must_have 覆盖率 100%，未覆盖项写明「由项目 N 覆盖」
- [ ] 任意两个候选在「技术栈 / 业务领域 / 硬骨头」三维度没有两项雷同
- [ ] 每个候选至少 1-2 个硬骨头模块，且写清问题/方案/trade-off/为什么能讲 10 分钟
- [ ] 工作量全部用「步骤轮次 + 卡点次数 + AI 协作系数」，全文搜不到「人天」
- [ ] MVP 最小可用场景是一句可验证的动作链（R18），不是「支持 XX 管理」
- [ ] 主动砍词清单齐全，理由能对应 `docs/个人项目不可实现清单.md`
- [ ] 无违反硬件约束的选型（7B+ 本地推理 / K8s / GPU 训练 / >5 服务）
- [ ] 选型与求职方向匹配（Java 后端 + 测试开发双栖，测试体系能真正落地）
- [ ] 面试三问已逐项目作答，不是占位
- [ ] `00_选题矩阵.md` 已落盘，且末尾有「待用户拍板事项」——产出后停住等卡点 1，不擅自进 0.5
