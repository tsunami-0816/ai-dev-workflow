## 效果度量

- **目标**：产出可运行的前端代码，install/dev/build 成功，首页与受保护页可达
- **启动前前置检查（D4）**：
  1. 先确认 `06.5_契约/openapi.json` 存在且 paths > 0
  2. 跑 `python scripts/api_contract_validator.py check 06.5_契约/openapi.json 05_代码/frontend` 预检一次
  3. 契约为空或路径数为 0 → 打回 step5A，不开始写前端
- **成功标准**：
  1. `npm install` 成功
  2. `npm run dev` 起服务，页面可访问
  3. `npm run build` 无报错
  4. 每条 P0 前端链路按用户操作路径走通
- **失败信号**：
  1. 路由守卫死循环 / 白屏
  2. 接口调用 404 / 401
  3. build 报错
  4. 5.5 reviewer 打回
- **度量方式**：`npm run dev` 起服务 + 浏览器走查 P0 路径 + 5.5 reviewer 通过

### 精修模式专属流程（R24；仅当看板「设计模式=精修」时执行）

> **普通模式：整节跳过**——功能跑通即算 5B 完成，不产出精修记录、不额外花时间；在 `_项目状态.md` / 交付说明记一行「设计模式=普通（跳过精修）」即可。
> **精修模式**：功能开发全部完成、功能自测通过后再进入本节。顺序不能乱：**先发散 3 版首页 → 用户挑 1 版 → 主循环改 2 轮 → 空上下文视觉评审 → 过 9 分线才准进 step06**。功能没跑通前不做精修。

**硬约束（防无限追求完美，违反任一视为流程违规）**

1. 视觉评审最多 2 轮（含首轮），2 轮仍 <9 记 `deferred`，不阻塞功能验收
2. 只改视觉，不改功能——不推翻架构、不重写组件库，只调颜色/间距/字体/对齐/布局比例
3. 视觉相关总耗时 1 小时就停，超时部分记 `_问题台账.md` 下版本
4. P0 功能问题永远优先——精修中发现功能 bug，先修 bug，精修往后排
5. 发散阶段只出**首页视觉稿**，不出全部页面，避免成本爆炸

**step 1 · 三版首页发散（先发散，不进入修 bug 循环）**

- 基于同一份功能要求（架构 + 任务拆解 + 已跑通的功能），用 **3 个差异极大的具体风格词**（例：像素风数据看板 / 45°等轴测 3D 城市 / 不和谐秩序不对称排版）+ 不同随机种子，各出 **1 版首页视觉稿**；
- 三版必须在**布局结构**上就明显不同，禁止「蓝 / 深蓝 / 浅蓝」式微调差异；
- 风格词必须具体可执行，禁止「现代 / 简洁 / 科技感 / 高级 / 大气」这类废词（对照 step02「§ 前端设计方向」的废词黑名单）；色值/字体/圆角/间距仍受 step02 设计方向约束，冲突时以 step02 为准；
- 每版留截图 + 一句话设计意图，登记进 `05_代码/frontend/设计精修记录.md` 的「三版发散」小节。

**step 2 · 用户挑 1 版（👤 必须用户选，AI 不得自选）**

- 把 3 版首页截图 + 差异说明交给用户，请其选 1 版；用户未选前不得自行进入主循环；
- 用户选定后，把「选定版本 + 用户理由（可选）」写进精修记录；只有选中的这一版进入后续主循环。

**step 3 · 精修主循环（在选中的那版上跑，最多 2 轮）**

1. **跑检测**：启动 dev server 后，运行 `python scripts/design_quality_check.py --url http://localhost:<前端端口>`，拿到 error/warning/advisory 级问题清单
2. **定方向**：对照 step02 产出的「前端设计方向」，看页面有没有跑偏（比如定了「深色科技感」结果还是白底蓝按钮）
3. **第 1 轮修改**：从检测结果 + 设计方向偏差里，挑 5 个最影响观感的问题改掉（比如侧边栏对比度不够、卡片 padding 太挤、字体大小不统一）
4. **重跑检测**：改完再跑一遍 `design_quality_check.py`，确认 warning 级减少
5. **第 2 轮修改（可选）**：还有明显问题就再挑 3 个改，然后停；**两轮封顶，不许开第 3 轮**
6. 每轮把「问题 → 改法 → 改前改后截图」写进精修记录

**step 4 · 空上下文视觉评审员（≥9 才过线，评审最多 2 轮）**

- 另起一个**干净上下文** agent（未参与 5A/5B 编写），**只喂页面截图，不喂代码、不喂设计方向文档**；
- 提示词：「你是顶尖 UI 团队设计总监。给这些页面截图打 1-10 分，挑出最像 AI 模板的 3 个地方，每条必须具体到能改成伪代码」；
- 评分 **≥9 → 通过**，把评分与意见写进精修记录；**<9 → 按意见改完再评**（这是第 2 轮评审），**评审最多 2 轮（含首轮）**；
- 2 轮仍 <9 → 记 `deferred`：写进精修记录 + `_问题台账.md`（P2 起、状态 deferred），并同步进 10.6 简历「诚实边界」；功能验收可继续，但 step09 视觉质量验收会核对「≥9 或已 deferred」；
- **禁止**由写代码的同一上下文（或 5A/5B 的 Agent 自己）自评替代。

**step 5 · 产出记录与放行**

- 精修记录必落盘 `05_代码/frontend/设计精修记录.md`，6 节齐全：① 设计方向（来自 step02）② 三版发散（截图 + 设计意图）③ 用户选定版本 ④ 第 1/2 轮修改与最终检测结果（error/warning/advisory 数）⑤ 空上下文视觉评审（评分/意见/轮次）⑥ 遗留问题与 deferred
- 精修完成后进入 step06 冒烟：R23 的 `design_quality_check.py` 与 taste 软观察照常跑；step09 视觉质量验收按「对照设计方向 / warning 清零 / 评审 ≥9 或 deferred」三项核对
- **精修模式没有精修记录 = 5B 未完成**；普通模式本节跳过、门禁不查精修记录
