### 分批开发（按链路分批，每批跑通再下一批）

> 与 5A 同一口径：页面文件攒一坨再统一验收，最后只会剩「能打开但走不通」。

- [ ] 按第 4 步「一条链路一组任务」分批实现，**每批写完立即 `npm run dev` + 按用户操作路径走通该批链路**再进下一批
- [ ] 每批在运行说明里记一行：批次号 / 覆盖的映射表编号（D-xx）/ 走通路径 / 结果

### 5B 完成定义（硬约束，缺一不得宣布 5B 完成）

> 页面文件写完 ≠ 用户能操作。以下每项都要有真实终端输出 / HTTP 返回 / 截图作证。

- [ ] `npm install`（或等价）真实执行成功，退出码 0
- [ ] `npm run dev` 真实启动成功，端口 LISTEN，控制台无 fatal 报错
- [ ] 首页与至少 1 个受保护页面对 HTTP 200 或正常渲染（`env_preflight.py --smoke <前端地址>` 可作证），不白屏
- [ ] **每条前端承担的核心链路按用户操作路径走通一次**（如「建 prompt → 建 dataset → 跑 run → 看结果」），每一步都有可观测结果；不允许只验证页面能打开
- [ ] 生产构建验证：`npm run build` 通过（dev 能跑 ≠ build 能跑）
- [ ] **回填 `_设计实施映射表.md`**：本步负责的每一行状态改 `⚠️已实现未验证`（真走通过的可改 `✅已实现已验证`），「实现落点」填真实页面/组件，「验证证据」填操作路径与结果。仍在 `❌未实现` 的 P0 行不得宣布 5B 完成
